# Implementation plan: curated apps (replace Composio) and Edits

## Objective

Replace the Composio integration with a small, curated set of **apps** that non-technical users can set up in under a minute, starting with **Edits** (Instagram's video editor, desktop app with a local MCP automation server).

User-visible outcome:

1. Composio is gone: no Composio keys in Settings, no Composio catalog, no Composio tools or prompt text in any Buddy turn.
2. The Apps screen lists curated apps. Each card shows a plain-language status: **Not installed / Not running / Needs setup / Ready**.
3. Clicking **Set up** on an app opens a configuration popup with numbered, non-technical steps, the fields that app needs (for Edits: access token, with the endpoint prefilled), and a **Test connection** button that checks the app live over the network before saving.
4. Buddies know which apps exist and their status. When a request needs an app capability (e.g. "make a montage from the clips in …"):
   - the matching app is **Ready** → the Buddy uses it;
   - it is **not set up** → the Buddy explains, step by step, how to set it up (and links to the Apps screen) instead of attempting the task;
   - **more than one Ready app** can do it → the Buddy asks the user which to use;
   - the user **tagged an app** in the composer → the Buddy uses that app without asking.
5. The composer gets an app picker: typing `+` (e.g. `+edits`) suggests apps, like `@` for Buddies, `#` for projects and `%` for tasks. Tagged apps render as chips in sent messages.

Out of scope for this plan: apps other than Edits (the registry is built to add them later), OAuth-based cloud apps, per-Buddy app permissions, auto-installing apps, and Buddies on drivers that cannot load MCP tools (see Risks).

## Proposed changes

### 1. Remove Composio

- Delete `server/composio.ts` and `server/composio.test.ts`.
- Remove the `composio` config section, its env fallback (`COMPOSIO_KEY`) and redaction entry from `server/config.ts`. On the next config write the stale `composio` block is dropped so no orphaned key is left on disk.
- Remove Composio routes, prompt injection and the `integrations.composio` turn field from `server/index.ts` and `server/contracts.ts`; remove the Composio MCP block from `server/drivers/claude.ts` and its tests.
- Remove the Composio key fields from `ApiKeys.tsx` / `SettingsScreen.tsx` and the `composio` flags from `store.tsx`.
- Update `README.md`, `SECURITY.md`, `docs/guide/glossary.md`, `docs/guide/copy-sweep.md` and the issue templates.
- `dist-server/` is regenerated by `pnpm build:server`, never hand-edited.

### 2. App registry (server)

- New `server/apps/catalog.ts`: a typed, curated list. Each entry: `id`, `name`, `blurb`, `category`, `capabilities` (plain words the Buddy matches against, e.g. `video editing`, `montage`, `captions`), `transport: "local-mcp-http"`, `defaultEndpoint`, `auth: { kind: "bearer", label: "Access token" }`, `setupSteps` (plain-language, numbered), `appUrl` (download page), and icon.
- First entry: **Edits**, default endpoint `http://127.0.0.1:19501/mcp`, setup steps: install Edits → open Settings → Automation → turn on *Enable Automation Server* → copy the Access token → paste it here → Test connection.
- New `server/apps/store.ts`: per-app settings in `~/.gbs/apps.json` (`endpoint`, `token`, `enabled`), written atomically and owner-only like `config.json`. Tokens are **write-only**: no API ever returns them, only `tokenConfigured: true`.
- Endpoints for `local-mcp-http` apps must be loopback (`127.0.0.1`, `localhost`, `::1`); anything else is rejected. This stops a pasted URL from sending the token off the machine.

### 3. Live status checks

- New `server/apps/health.ts`: `checkApp(id)` performs an MCP `initialize` + `tools/list` against the endpoint with a short timeout (5 s) and maps the result to:
  - connection refused → **Not running** ("Open Edits and turn on Automation");
  - 401/403 → **Needs setup** (token missing or wrong/regenerated);
  - success → **Ready**, with the tool count and tool names cached;
  - anything else → **Error** with a readable message.
- **Not installed** detection is optional and platform-specific: an Electron helper behind `process.platform === "darwin"` checks for `Edits.app`; elsewhere the status falls back to "Not running".
- Statuses are cached ~30 s and refreshed on Apps screen open, on Test connection, and before each Buddy turn that receives app context (cache hit in the common case, so turns are not slowed).

### 4. Routes

- `GET /api/apps` → catalog + status (no tokens).
- `PUT /api/apps/:id` → save `{ endpoint?, token?, enabled? }`.
- `POST /api/apps/:id/test` → check using the submitted, unsaved values so the popup can validate before saving.
- `DELETE /api/apps/:id` → disconnect (clears token).
- Internal (`COMMS_TOKEN`-guarded, localhost-only like the existing agents endpoints): `POST /api/internal/apps/:id/mcp` → forwards a JSON-RPC message to the app with the stored token injected.

### 5. Buddies use apps through the harness

- Extend the existing harness-owned proxy rather than adding per-driver configuration: `agents-proxy.ts` exposes two generic tools to every MCP-capable driver:
  - `list_apps` → each app's status, capabilities and, when Ready, its tool names and schemas;
  - `use_app(app_id, tool, arguments)` → forwards to the internal route above and returns the app's result.
- Why this shape: one implementation reaches Claude, Codex and ACP Buddies; the token never appears in CLI args, driver config or the agent's environment; the harness can refuse calls to apps that are not Ready; and adding the next app needs no driver changes.
- Prompt: `server/apps/prompt.ts` builds a short **Apps** section, added only when `capabilities.agentsMcp` is true (fixing the overpromising found in testing). It lists each app with status and capabilities and states the rules from the Objective (use if Ready, give setup steps if not, ask when more than one fits, a `+app` tag wins). Buddies on drivers without MCP get no app section.

### 6. Apps screen and setup popup (renderer)

- Rewrite `AppsScreen.tsx` around `/api/apps`: a grid of curated app cards with a status pill and a single primary action (**Set up** / **Open setup** / **Disconnect**). The Composio-specific categories, spotlight and catalog code are removed.
- New `AppSetupDialog.tsx`: the app's numbered steps, an endpoint field (prefilled, under "Advanced"), a token field (password-style, never shows the saved value), **Test connection** showing the live result in plain words, and **Save** (enabled after a successful test, or with a warning if skipped).
- Accessible: focus trap, Escape to close, labelled fields, status communicated in text not just colour.

### 7. `+app` tags in the composer

- New `src/lib/appMentions.ts` (mirrors `projectMentions.ts`): `+` at a word start, followed by an app id, case-insensitive; digits after `+` (phone numbers) never match.
- `Composer.tsx`: add `app` to the closest-trigger arbitration; new `AppSuggestionList` shows app icon, name, and status (not-ready apps are still selectable so the Buddy can explain setup).
- Render known `+app` tokens as chips in direct and room user bubbles.
- Harness: resolve `+app` tags in the latest user message server-side and add "The user chose: Edits" to the app prompt section.

## Verification

Automated (`pnpm typecheck`, `pnpm test`, using the fakes in `server/testing/` and a temp `GBS_DATA_DIR`, never the real `~/.gbs`):

- Composio is gone: no `composio` in source outside history docs; config loading ignores and drops a legacy `composio` block.
- App store: token write-only (never in any response), atomic owner-only write, non-loopback endpoints rejected.
- Health: a fake local MCP server returns refused / 403 / success / malformed responses, mapped to the four statuses; timeout respected.
- Proxy: `list_apps` / `use_app` forward correctly; calls to a not-Ready app are refused; the token never appears in proxy env or args.
- Prompt: the app section appears only for `agentsMcp` drivers; a `+edits` tag is reflected; no section when no apps are configured.
- Composer: `+` trigger parsing, arbitration with `@` `#` `%`, phone numbers ignored.

Manual, in an isolated second Electron instance (per desktop QA practice), with the real Edits app:

1. Edits closed → card shows **Not running**; open Edits with Automation off → still Not running; turn it on → **Needs setup**.
2. Set up with a wrong token → Test shows a readable failure; with the right token → **Ready** with tool count; regenerate the token in Edits → status returns to Needs setup.
3. Ask a Claude Buddy and a Codex Buddy "make a short montage from the clips in `TEST · montage clips`" → each lists apps, calls Edits, and the project appears in Edits.
4. With Edits disconnected, the same request → the Buddy gives setup steps and does not claim success.
5. `+edits make a montage…` → no "which app?" question.
6. Antigravity Buddy (Marty) → no app section in its prompt and an honest "I can't use apps on this model" reply.
7. Apps screen at desktop and narrow window widths; keyboard-only setup flow.

The Edits tool list is not known yet (the server needs the token). The first implementation step records the real tool names and confirms that clip import from a folder is supported. If it is not, the montage scenario will be adjusted and reported before going further.

## Risks and rollback

- **Drivers without MCP** (Antigravity, Grok direct, native) cannot use apps. The Apps screen notes "Works with Buddies on Claude, Codex and Gemini". Moving Marty to the Gemini ACP driver would give it apps.
- **Edits API changes** (it is new): the integration only depends on standard MCP plus Bearer auth, and the tool list is discovered live, not hardcoded.
- **Token exposure:** stored owner-only, never returned or logged, never in child-process args or env, loopback-only endpoints.
- **Removing Composio** drops Gmail/GitHub/etc. access for Claude Buddies. This is intended. Codex Buddies keep their own built-in connectors, which are outside this app.
- **Rollback:** the work lands as separate commits (Composio removal; registry and health; proxy and prompt; UI; composer tags). Reverting the later commits disables apps without bringing back Composio; reverting the removal commit restores Composio.

## Decisions (2026-11-19)

1. **Tag character:** `+` (`+edits`). Approved.
2. **Old Composio key:** deleted from `~/.gbs/config.json` on the next config load. Approved.
3. **Model support is visible (added by the user):** every app card and the setup popup show which AI providers can use the app (tags such as *Claude*, *Codex*, *Gemini*, plus a muted *Not supported* list). Support is derived from each provider instance's driver `capabilities.agentsMcp`, so it stays correct as drivers change. The composer `+app` picker shows a warning when the current Buddy's model cannot use apps.
