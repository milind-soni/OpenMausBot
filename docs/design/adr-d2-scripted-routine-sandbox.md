# ADR — D2: Scripted routine sandbox runtime

**Revision v3 (2026-09-26).** Answers Red Team's v2 delta check (section 7 of `.../6ea2f342-f4c9-49cf-994e-b92cbbc53e6f/d2-sandbox-adr-red-team-review.md`): all eight original findings confirmed closed, and the seven new items are folded in here — N-1 (fd relabel), N-2 (buffered frame cap), N-3 (request budgets), N-4 (protocol terminality), N-5 (watchdog overshoot named), N-6 (address normalization), N-7 (`process.kill`/`process.abort` neutering) — with section 9 extended to assert N-2, N-3, N-6, and N-7. Red Team's verdict with these folded in: the design is ready for the D2 build behind the prototype flag in server mode; Chief verifies v3 and holds the dispatch decision. v2 is superseded in place.

**Errata (2026-09-26, CodeRabbit fix round on the build).** The build's first review round surfaced eight places where the shipped code sharpened or corrected statements above; the corrections are now the contract:

- **N-3, outstanding slot (section 4/5):** the outstanding-request slot is held for the **whole fetch including its redirect chain** — it is released only when the fetch settles, not per hop, so a 5-frame chain cannot occupy two slots or slip a 5th concurrent request past the cap.
- **N-4, post-settle guards (section 3/5):** the terminality rule is enforced defensively at every await in the host fetch path — after DNS resolution, at each hop entry, and on every resume — not only at frame-service time; hop timers are bounded by the run's **remaining wall clock**, not restarted per hop.
- **Credentials (section 4):** an entry binding a credential to a plain-http host requires an additional explicit `allowHttpCredential` opt-in, and even then only a pinned loopback address qualifies; the credential is resolved **after** DNS/allowlist validation so no secret work happens for a request that will be denied. https entries need no opt-in.
- **Neutered internals (section 3):** the canary list is seven, not six — `function_ctor_blocked` joins it, because `delete globalThis.Function` alone leaves the constructor reachable through function/object prototypes; all four prototypes now carry throwing getters.
- **Host-to-child channel cap (section 5 volumes):** fd 0's per-frame cap is sized to the **worst-case JSON escaping** of a max response body (13 MiB), not its raw 2 MiB — a body of escape-heavy bytes is larger on the wire than in memory, and the raw-sized cap rejected bodies the response cap had allowed.
- **Lifecycle (sections 3/7):** dispatch of a scripted run is **asynchronous** — the scheduler tick does not block on the child (up to 300 s), other routines keep dispatching, and per-routine in-flight state is tracked separately; cancel/disable and server shutdown **abort** the in-flight child (a settled outcome arriving after an abort is dropped, so it cannot overwrite the cancelled status); shutdown awaits all aborted runs before proceeding.
- **Results (section 6):** `run.result` passes through `redactSecrets` **before persistence and emission**, not only `redactSecretsInText` at surfacing — a credential-shaped value must never reach the stored receipt.
- **Host channel robustness:** the host attaches an error listener to the child's stdin so an aborted child death mid-write cannot surface an async EPIPE as an uncaught server exception.

**Status:** Proposed — Chief holds the dispatch decision; the Red Team gate target is section 9. On landing, the build slice places a copy in the repo docs tree; nothing is committed by this dispatch.

**Verified base:** upstream milind-soni/OpenMausBot main at `7850a1ac`, re-verified by `git ls-remote` at v3 rework time and independently by Red Team the same day (note: the bradhallett fork's main has diverged; every cite here resolves against milind-soni main). Permission-model claims are empirical on Node v26.10.0 (section 8); the repo floor is Node >= 24 (`package.json` engines), CI pins 24, and the packaged desktop is Electron `^43.4.0`, whose embedded Node is a canary question, not an assumption (sections 8-10).

## Decision (five lines)

1. **Runtime:** plain JavaScript, executed as source in a child of the server's own binary, spawned fresh per run with Node's permission model on and **zero** `--allow-*` flags, and with the bootstrap **neutering the internal process surface** — `_linkedBinding`, `binding`, `dlopen`, `_debugProcess`, `kill`, `abort` — before the script context exists.
2. **The script's whole world** is a reduced context inside the child: an injected `fetch` shim, `state.get/put`, a captured `console`, bounded timers, and safe intrinsics; `eval`, the `Function` constructor, dynamic `import()`, and `WebAssembly` are neutralized alongside the internals above.
3. **Network is host-mediated only:** the shim speaks a dedicated, typed, size-capped channel; the server re-validates the reviewed allowlist, resolves the hostname itself, normalizes every resolved address (IPv4-mapped IPv6 unwrapped, zone ids stripped), and denies loopback, unspecified, private, link-local, CGNAT, multicast, benchmark, and cloud-metadata ranges unless the entry explicitly opts in; it connects pinned to a validated address, resolves credentials server-side, and returns a sanitized response. A denial fails the run loudly, naming the host or range.
4. **Scripted runs never consume admission for a turn and never touch VM/desktop seats:** the dispatch branch lands after the missing-target continue and before the createTask block (routines.ts:1573-1577 vs 1579-1589, verified), so no task or thread exists; the unattended botState gate still executes first via `unattendedDispatchState` (index.ts:1933, wired at :8980 and :9827).
5. **v1 scope:** scripted routines run only in parent modes the build-gate canary has proven — today that is a plain Node >= 24 server (dev, CI, self-hosted). Electron-embedded mode ships dark behind the prototype flag until its canary passes in the packaged build; promotion requires no design change.

## 1. Context and hard inputs

Issue #1506 mode 3: a routine may execute a generated script on schedule with zero LLM calls, sandboxed by a capability allowlist, versioned and review-gated so edits restage before the next run. The decomposition recommended this runtime and gated the build on this ADR; Red Team reviewed v1 (needs changes, R-1 through R-8), then delta-checked v2 (section 7 of the review: all eight closed, seven new items returned, none architectural); this revision folds in those seven. Hard inputs, restated:

- **Zero new dependencies.** No sandbox library, no second runtime binary, no native addon enters through this slice.
- **Open PR #1879 fences** `server/routine-requests.ts` and `shared/routine-request.ts`. This ADR fixes stored-contract shapes only; the propose/update validation that enforces them lands after that PR merges.
- **Scripted runs stay off VM/desktop seats** (the #1843 note in the decomposition): no seat requests, no lease pool, no box dispatch, no host fallback.

## 2. Candidates and their threat surfaces

| Candidate | Boundary | Threat surface | Verdict |
|---|---|---|---|
| Child Node + permission model + neutered internals | OS process + syscall-level allowlist + deleted internal escape hatches | Flag/env injection from the parent (constants-only argv, scrubbed env); context escapes (shim-only surface); resource exhaustion (heap flag, RSS watchdog, wall clock); version drift (runtime canary) | **Chosen** |
| QuickJS-WASM in-process | WASM linear memory | Every host function bridged into the VM is a hand-written escape hatch; supply-chain review of the WASM artifact; perf tax; no real crypto/URL without more bridges | Rejected: new dep, more bridges, no stronger boundary |
| isolated-vm | Native isolate threads | Strongest CPU/time isolation, but a native dependency with per-platform build friction and abandonment history; transferable-handle mistakes are escape hatches | Rejected: violates zero-new-deps; revisit only if the child model fails a gate item |
| node:vm or worker_threads in-process | None that matters | Same process, same env, same credential memory; every escape is a full compromise | Rejected outright: not a security boundary |
| VM hop (Box/Local VM) | Full machine | Strongest isolation but consumes VM seats, adds spin-up latency and per-run cost — reintroducing what the deterministic mode exists to remove | Rejected; heavy work escalates to a computer lane (D3), the sandbox does not widen |
| Deno / Bun / Python child | OS process | Each is a second runtime to ship, patch, and secure | Rejected: no boundary gain over Node's |

## 3. Process boundary, capabilities, lifecycle

Spawn shape (server-controlled constants only):

```
spawn(process.execPath, [
  "--permission",
  "--max-old-space-size=256",                  // heap hygiene only; the process cap is the RSS watchdog (section 5)
  "-e", BOOTSTRAP_SOURCE,                      // fixed, server-shipped; never routine content
], { env: CLEAN_ENV, stdio: ["pipe", "pipe", "pipe", "pipe"], windowsHide: true })
```

- **One flag rule, no fallback branch (R-2).** The stable `--permission` spelling only. Scripted routines refuse to run on any runtime where the canary cannot prove process-level network and spawn denial — today that means plain Node >= 24, which is already the repo floor, so refusing costs nothing. There is no Node 20-22 path: on those runtimes the child's own network is unfenced and `_debugProcess` is callable (Red Team demonstrated an inspector forced onto 127.0.0.1:9229 from a zero-flag permission child), which converts the shim-only fallback into a server-RCE chain. The shim is a fetch fence, not a signal fence.
- **Neutered internals (R-1, extended by N-7).** Before the script context is created, the bootstrap deletes or wraps to throw: `process._linkedBinding`, `process.binding`, `process.dlopen`, `process._debugProcess`, `process.kill`, and `process.abort`. Why each: `_linkedBinding` reaches Node internals without the addon permission check — and Electron's main line exempts every `electron_*` name from that check in `ELECTRON_RUN_AS_NODE` mode, while the 43-x line may predate the gating entirely; `binding` is the legacy internal loader; `dlopen` loads native addons around `--allow-addons` semantics; `_debugProcess` forces a V8 inspector onto an arbitrary pid; `process.kill(pid, "SIGUSR1")` is gated by no permission scope — Red Team demonstrated, and the requester independently reproduced on Node v26.10.0, a zero-flag `--permission` child forcing an inspector onto another Node process at 127.0.0.1:9229 (same class as `_debugProcess`), and it equally enables same-user SIGKILL denial of service; `process.abort` raises SIGABRT in-process and is removed for completeness. The canary asserts each of the six throws, in both parent modes, before the mode is enabled.
- **CLEAN_ENV inherits nothing, and the scrub is load-bearing.** Red Team verified `NODE_OPTIONS="--allow-fs-read=/"` dissolves the fence completely. Excluded: `NODE_OPTIONS`, `NODE_EXTRA_CA_CERTS`, all proxy variables, `PATH`. Kept: `TZ`; and `ELECTRON_RUN_AS_NODE=1` only when the parent is Electron (a mode that is dark in v1 until its canary passes). The script and run manifest travel as the first framed line on stdin, never argv.
- **Channels (R-4, hardened by N-1/N-2/N-4).** Four fds, each with one job:
  - **fd 0, host to child, framed NDJSON:** first frame = run manifest; later frames = `{ id, type: "fetch-response", ... }` keyed to outstanding requests.
  - **fd 1, child to host:** exactly one terminal JSON result line — terminal for the **whole protocol**, not just fd 1: once the result line is received, the host stops servicing the shim channel entirely, discards queued frames, sends no further fetch responses, and expects the child to exit (N-4). A child that keeps fetching after emitting its result races frames against a closed envelope; the contract forbids servicing them.
  - **fd 2, child to host:** crash diagnostics only, 4 KiB cap.
  - **fd 3, child to host, shim NDJSON (N-1):** with a four-pipe `stdio` array the fourth pipe is the child's **fd 3** — fd 4 does not exist in the child (empirically verified by Red Team: a marker written to `stdio[3]` arrives on fd 3). We keep the four-pipe array and label the channel fd 3; a fifth pipe would buy nothing. Frames are `{ id, type: "fetch", method, url, headers, body }` requests; per-frame cap 256 KiB enforced **while reading, before the newline** (N-2): the host counts bytes incrementally, and an oversized or unterminated frame aborts the run as `crash` (detail `shim_frame_limit`) — a cap applied only at the newline would leave server memory unbounded against a newline-less flood. Ids are monotonic per run.
  Every child-emitted byte is hostile input at webpage-content trust level: zod-validated, size-capped, unknown fields ignored, and the server re-derives all policy — allowlist membership, credential binding, redirect and range rules, budgets, caps — from its own routine record, never from frame fields. The script's `console` is an injected in-memory shim (64 KiB cap) returned inside the result envelope.
- **Lifecycle.** Spawn per run, no pooling. Success = result envelope received **and** exit 0. Timeout: per-routine `timeoutSeconds` (default 30, hard cap 300) then SIGTERM, 2500 ms grace, SIGKILL (Windows maps both to termination; parity is a gate item). Server shutdown kills and reaps all in-flight children. No grandchildren: `spawn()` inside the child throws `ERR_ACCESS_DENIED` under the permission model (verified, section 8). One live child per routine id; a second tick while one runs defers with the existing `deferredAt` stamps (routines.ts:1553-1575, verified).

## 4. Host-mediated fetch: the allowlist contract

**Who declares hosts:** the bot proposes the script, its allowlist, any credential bindings, and (later, with D3) escalation rules as **one staged review unit**, mirroring `stageSkillWrite` (skills.ts:1177). A human approves before the script ever runs; any edit restages; the stored script version's sha256 is verified pre-run and a stale or unstaged version refuses to execute.

**Where it is stored:** on the routine record in server-protected config (outside any bot-readable workspace), zod-validated, with the editor-visible subset on the wire. Entry shape:

```
networkAllowlist: [{ host: "api.github.com", credentialId: "gh-status", allow: ["loopback"] }]
```

- `host` is an exact hostname: no wildcards, no IP literals, no userinfo forms. `scheme` defaults to https; http requires an explicit entry; custom ports must be declared. `allow` is the explicit, reviewed opt-in for otherwise-denied address ranges (below); absent means all ranges denied.
- **Resolve-then-connect (R-5, hardened by N-6).** The host resolves the hostname itself and **normalizes every result before any range check**: IPv4-mapped IPv6 (`::ffff:0:0/96`) is unwrapped to its IPv4 form (a mapped 127.0.0.1 must hit the loopback check), and IPv6 zone ids are stripped. It then checks **every** A/AAAA result against the denied ranges — loopback (127/8, ::1), unspecified (0.0.0.0/8 and ::, treated as denied outright — they are connect targets, not ranges to dial into), private (10/8, 172.16/12, 192.168/16, fc00::/7), link-local (fe80::/10, 169.254/16), CGNAT (100.64.0.0/10), multicast (224.0.0.0/4, ff00::/8), benchmark (198.18.0.0/15), and cloud metadata (169.254.169.254, named explicitly) — and denies with an error naming the range unless the entry opted in. The connection is then pinned to a validated address, closing the check-to-connect window; TLS SNI and certificate verification stay against the declared hostname. Every redirect hop is re-resolved, re-normalized, and re-checked (max 3, cross-host to an unlisted host is a named denial). A listed host that legitimately flips addresses between runs is the remaining rebinding case: per-entry IP pinning is the v2 answer, recorded here so the contract does not silently widen.
- **Request flow, caps, and budgets (N-3):** shim frame to fd 3, host re-validates policy from the routine record, resolves any bound credential and attaches it server-side, performs the call (request body <= 256 KiB, response body <= 2 MiB, beyond: `response_too_large`), strips `set-cookie`, `www-authenticate`, and hop-by-hop headers, returns `{ status, headers (subset), body (text), truncated }` on fd 0. **Budgets:** at most 4 outstanding shim requests and at most 50 requests total per run; a fifth outstanding or a fifty-first total fails the run loudly as `request_limit` (the receipt names which bound was hit). Without these, one reviewed allowed host turns the server into an egress amplifier inside the timeout window — each response is capped at 2 MiB, but the count was unbounded.
- **Credentials:** bearer-only in v1, bound per entry, resolved by the host at call time through the server's existing credential seams (`CREDENTIAL_TARGETS` / `credentialIsConfigured`, index.ts:15391-15392). The secret is never present in the child, any frame, state, logs, or results.
- **Failure mode on denial:** default is fail-loudly — the run fails with `policy_violation` naming the denied host or range. A script may mark a specific request `optional: true` in code a reviewer sees; that denial becomes a catchable error plus a receipt warning. No frame-supplied flag can soften policy.

## 5. Resource, timeout, and kill guarantees

- **Memory (R-3, corrected; residual named by N-5):** `--max-old-space-size=256` bounds V8 old space only — ArrayBuffers and Buffers are external memory and grow past it — so it is hygiene, not the guarantee. The guarantee is a **host-side RSS watchdog**: the server samples the child's RSS every 2 seconds (Linux: `/proc/<pid>/statm`; macOS: `ps -o rss= -p <pid>`; Windows: `tasklist` CSV), trusts nothing the child reports, and kills through the normal SIGTERM-to-SIGKILL path when `rssLimitBytes` (default 512 MiB) is exceeded; the receipt records `crash` with detail `rss_limit`. The wall-clock deadline bounds everything even if a sample is missed.
- Wall clock: `timeoutSeconds` (default 30, cap 300); SIGTERM, 2500 ms grace, SIGKILL; kill confirmed before the receipt is written.
- CPU: no hard quota (named residual: a busy loop burns one core until the wall clock kills it).
- Volumes: result envelope <= 64 KiB; stderr 4 KiB; console 64 KiB; state 64 KiB per routine; shim frame 256 KiB (enforced while buffering, N-2); request 256 KiB; response 2 MiB; shim requests 4 outstanding / 50 total per run (N-3).
- Concurrency: one child per routine id; overlap and `deferredAt` semantics identical to today.
- Lifecycle: server shutdown reaps; a kill during an in-flight host fetch aborts the server-side request too (gate item).

## 6. Results and artifacts: the return path

- **Protocol:** the child writes exactly one JSON line to fd 1: `{ ok, value?, logs, warnings }`. The host validates shape and size, never parses stderr as protocol, and treats early close as `crash`. After the result line the host services nothing further on any channel (N-4).
- **Receipt (additive fields on RoutineRun):** `exitCode`, `durationMs`, `scriptVersion` (sha256), `deterministic: true`, `result` on success, and on failure `failure: { kind, detail, deniedHost? }` with kinds `timeout`, `crash` (incl. `rss_limit`, `shim_frame_limit`), `policy_violation`, `request_limit`, `script_error`, `state_error`, `response_too_large`. The propose/update validation lands after open PR #1879 merges; this ADR fixes the shapes.
- **Surfacing:** receipts flow through the existing `emitRun`/`cloneRun` path (routines.ts:459) to the run-card surface, rendered from data exactly as D1's structured output renders, with a deterministic marker. Any result text that reaches a transcript or card passes `redactSecretsInText` (the module routines.ts imports at :9).
- **Cross-run artifacts:** the `state.get/put` API (JSON, <= 64 KiB, host-persisted per routine id) is the artifact channel and the thing D3's "output changed" trigger diffs. No filesystem artifacts in v1: the child has no fs; a real artifact-writing case reopens this with a scoped `--allow-fs-write=<dir>` as a separate reviewed decision.

## 7. Composition with admission, and D3 consequences

- **Scripted runs never consume admission for a turn (R-7, reworded).** The unattended botState gate still executes before any branch: the RoutineManager and WebhookManager are constructed with `botState: unattendedDispatchState` (index.ts:8980 and :9827), which calls `admit("unattended")` (index.ts:1933-1943) — a pure decision that consumes no seat and no thread. Implementers must not bypass `targetState`: missing-target failures and overlap-busy deferral live there, and losing them loses honest failure modes.
- **Exact insertion point (R-6, corrected):** the scripted branch lands after the missing-target continue (routines.ts:1573-1577) and **before** the createTask block (routines.ts:1579-1589), both verified on `7850a1ac`. The run is marked running, the child executes, the receipt is written, the loop continues — no task, no thread, no orphan to clean up. Occurrence windows, same-routine overlap, and missing-target gating all still apply. (v1's "before startTurn at 1596-1620" described the wrong window: createTask at 1579 would already have allocated the orphan.)
- **Every LLM-producing path keeps today's admission.** D2 changes no admission code; D3's escalation turn goes through the same unattended path with `deferredAt` deferral when the target is busy. The `peer` surface is untouched: scripts never dispatch to teammates, and a future slice that wants script-driven delegation becomes a new `admit()` consumer, not an edit to server/admission.ts.
- **D3 consequences, fixed now:** escalation rules live in the same staged review unit as script and allowlist; they are pure data (field/operator/value plus diff-against-previous receipt/state, per Brad's #1506 reply), evaluated host-side after the scripted run completes. A firing rule creates a normal scheduled LLM run whose prompt carries the script result and diff summary through the existing carry pattern (`composeExecutionPrompt`, defined routines.ts:488, invoked at :1619 — both verified); receipts link the script run id to the escalation run id.

## 8. Empirical verification recorded at ADR time

Mine (Node v26.10.0, 2026-09-26, against main `7850a1ac`): `readFileSync` throws `ERR_ACCESS_DENIED`; raw `net.connect` and `fetch` fail with `ERR_ACCESS_DENIED`; `spawn()` throws `ERR_ACCESS_DENIED` (module load is not gated, the syscall is); all four v1 internals exist as callable functions under `--permission`, and `binding('fs')` throws when called.

Requester reproduction (Node v26.10.0, 2026-09-26, per the v3 fold-in request, matching Red Team's proof): `process.kill(pid, "SIGUSR1")` from a zero-flag `--permission` child **succeeds**, forcing a V8 inspector onto another Node process at 127.0.0.1:9229 (drives N-7).

Red Team's (Node v26.10.0, macOS, same day, from the review folded in here): `NODE_OPTIONS="--allow-fs-read=/"` under `--permission` **succeeds** — the env scrub is load-bearing; `process._debugProcess(pid)` **succeeds** from a zero-flag permission child, forcing an inspector onto 127.0.0.1:9229 (drives R-1/R-2); `_linkedBinding('electron_common_asar')` is gated under plain Node but exempted by Electron's main-line patch, which is absent on 43-x; Electron 43 embeds Node 24.14.0. v2 delta: with `stdio` of four pipes, a marker written to `stdio[3]` arrives on the child's **fd 3** — fd 4 does not exist (drives N-1).

Base integrity: upstream re-verified at `7850a1ac` (again at v3 rework); the working clone is clean; no open PR, worktree, or `/Projects/OpenMausBot` was touched.

## 9. Red Team fixed target (build gate)

Each item is a written attack with a result in the gate report; CI keeps a fast subset.

1. Flag and env injection: inherited `NODE_OPTIONS`/`NODE_EXTRA_CA_CERTS` cannot widen the fence (the Red Team `--allow-fs-read=/` replay must fail); env scrub verified byte-for-byte; argv is constants-only; and `_linkedBinding`, `binding`, `dlopen`, `_debugProcess`, `kill`, `abort` each throw in **both** parent modes (N-7), with the Electron-embedded canary covering them, not just fs/net/spawn.
2. Context escape: `Function` constructor, `eval`, dynamic `import()`, WebAssembly, prototype pollution reaching host objects, `Error.prepareStackTrace` scraping, Symbol/species tricks against the fetch shim's thenables, `_linkedBinding('electron_common_asar')`, and direct `process.kill` / `process.abort` calls (N-7).
3. Allowlist bypass: userinfo URLs, case/punycode/trailing-dot confusion, port smuggling, scheme downgrade, redirect chains hiding an unlisted target, and a listed host resolving to loopback/private/link-local/metadata — including IPv4-mapped (`::ffff:127.0.0.1`), unspecified (`0.0.0.0`, `::`), CGNAT (100.64/10), multicast, and zone-id forms after normalization (N-6) — being denied, with the denial lifting only under an explicit per-entry opt-in.
4. Credential containment: the secret appears nowhere — frames, stderr, state, result, logs — on success and error paths; stripped headers verified; state cannot replay a credential.
5. Resource exhaustion: caps under flood; a newline-less flood and an oversized frame on the shim fd abort as `crash`/`shim_frame_limit` with the server's buffering memory bounded (N-2); request budgets enforced — a fifth outstanding and a fifty-first total each fail loudly as `request_limit` (N-3); an ArrayBuffer/external-memory flood versus the RSS watchdog (kill lands, receipt written, host unaffected); allocation-heavy scripts die as `crash`; timer bombs versus the deadline; fork-bomb attempt fails at `spawn()`.
6. Lifecycle: SIGTERM-to-SIGKILL on all three OSes; shutdown reaping; concurrent-tick deferral; an in-flight host fetch aborted with the child; post-result shim frames are never serviced (N-4); no orphan task or thread when the scripted branch is taken (insertion-point regression test).
7. State abuse: capped, isolated per routine, excluded from prompt and log surfaces by default.
8. Review-gate integrity: editing script, allowlist, or rules without restage never executes; sha256 pin verified pre-run; stale staged versions refuse.
9. Platform parity: every item on macOS, Linux, and Windows, plus the Electron 43-specific probe in the packaged build — its embedded 24.14.0 predates or lacks the gating the main-line patch exempts, so the canary probes and does not assume.

## 10. v1 scope decision (R-1), residuals, consequences

**Decision: v1 is server-only under the prototype flag, expressed as a canary-gated parent mode.** The bootstrap ships the R-1/N-7 neutering now, in every mode; scripted routines simply refuse to run in any parent mode the canary has not proven (fs, net, spawn denials plus the six neutered internals). Today that is a plain Node >= 24 server — dev, CI, self-hosted, and the packaged-server smoke — which the feature's prototype flag makes a costless scope: nobody has scripted routines yet. Why not the alternatives: **pinning a real Node binary** bundles a second runtime into the desktop app — size, macOS codesigning and notarization, another update channel — for a prototype feature, and buys safety only if Electron's embedded Node is actually weaker, which is unproven; **asserting Electron mode is safe today** would assume exactly what the canary exists to prove, repeating the v1 sin Red Team flagged (they could not verify Electron 43 locally either). Promotion is a passing canary in the packaged build, requiring no design change.

Named residuals: CPU starvation is bounded only by the wall clock; the RSS watchdog bounds **sustained** RSS, not peak — a burst allocation can transiently pressure the host inside the 2 s sample window before the kill fires (N-5, accepted alongside the CPU residual); DNS rebinding across runs is mitigated at connect time but not pinned per-entry (v2 of the allowlist contract); Windows RSS sampling granularity is coarser (`tasklist`); and the sandbox defends against mistakes and data-driven injection in reviewed code, not a determined adversary already inside the reviewed unit — the review gate is part of the boundary.

Consequences: the server owns a small, constant, testable bootstrap and shim; receipts grow additive fields (wire and card work); failure modes stay deliberately loud; the D2 build sequences its propose/update validation after PR #1879 merges while the runner lands behind the prototype flag, server-mode only.
