# Issue #1635 — Threads in update order, and pinning

## 目的

スレッド一覧を、そのスレッドが最後に更新された順に見せる。ピン留めしたスレッドは、その順より上に残す。

いまの一覧は、注意が必要なスレッド（waiting / working / queued / unread / 開いているスレッド）を上に浮かべ、それ以外は保存配列の順である。保存配列は作成時に先頭へ足すだけで、会話を続けても動かない。ボットはピン留めできるが、スレッドはできない。

## スコープ

- デスクトップのサイドバー、折りたたみ時の他スレッド、All-threads ピッカー
- iOS のスレッドツリーと管理シート
- Android のスレッドツリーとスレッドシート
- ボットのスレッドと、ユーザー作成チャンネルのスレッド
- ピンの保存と、三クライアントからの付け外し

## 非スコープ

- スレッドのドラッグ並べ替え
- メッセージのピン（`pinnedMessageId`。既存のまま）
- ボット自体のピン、フォルダの保存順、Attention inbox の順位
- 作業ディレクトリの pin（`cwd` / `pinnedCwd`）の意味を変えること

## 用語

- **更新時刻**: そのスレッドの最新メッセージの `at`。メッセージが無ければ作成時刻 `createdAt`。
- **ピン**: 人が付けた印。付いているスレッドは、付いていないスレッドより上に出る。ピン同士も更新時刻が新しい順。

## 受け入れ条件

1. メッセージがあるスレッドは、最新メッセージが新しいほど上に出る。メッセージが無いスレッドは作成時刻を使う。同時刻はこれまでの配列順を保つ。
2. `pinned: true` のスレッドは、ピンしていないスレッドより上に出る。ピン同士は更新時刻が新しい順。
3. waiting / working / unread / queued はバッジや状態表示のまま残る。これらは並び順を変えない。
4. デスクトップの既定一覧は、開いているスレッドのうち更新が新しい 6 件を出す。ピンと、注意が必要なスレッドと、今開いているスレッドは、この 6 件に数えず、その外でも残る。閉じたスレッドとアーカイブしたスレッドは、ピンされているか注意が必要なときだけ残る。
5. 「すべて表示」と検索は、畳みを外したうえで同じピン＋更新順に並べる。検索の一致条件は変えない。
6. ピンはスレッドの操作メニューから付け外しできる。作業中でも付け外しできる。アーカイブや削除は兼ねない。再起動後も残る。
7. ピンしたスレッドは、閉じていてもアーカイブされていても、既定の一覧に残る。
8. チャンネルのスレッドも同じ順序とピンを持つ。bot-to-bot の DM は従来どおり 1 スレッドのまま。
9. `updatedAt` はサーバが決める。クライアントからの PATCH では書けない。`pinned` 以外のスレッド設定の認可は変えない。
10. フィールドを知らない古いコンパニオンは、未知キーを無視して従来どおり動く。
11. iOS と Android の行に出る相対時刻は、作成時刻ではなく更新時刻である。デスクトップの行は時刻を出さない（現状維持）。

## 制約

- デスクトップ、iOS、Android で順序の規則は同じにする。フォルダの並びは各クライアントの現状を維持する（デスクトップは「先頭に来るスレッド」にフォルダが付いて動く。モバイルは保存したフォルダ順）。
- Attention inbox（「対応が必要なもの」の別リスト）の順位は変えない。
- `updatedAt` を毎メッセージで `bots.json` も `groups.json` も書き出さない。起動時の埋め直しは、変わったファイルにつき一度だけ保存する。
- フォルダの中のスレッド順は三クライアントで同じ（ピン、それから更新が新しい順）。フォルダ同士の順はデスクトップと iOS が、そのフォルダで一番上に来るスレッドに合わせて動く。未整理のスレッドはフォルダのあと。Android は保存したフォルダ順のまま。
- ベルと Updates は注意順のまま。折りたたんだサイドバーの「他のスレッド」には、注意が必要なものに加えてピンも残す。
