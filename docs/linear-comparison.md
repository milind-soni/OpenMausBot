## Structured comparison and implementation recommendations

| Area | Linear reference observed | Origin observed | Concrete changes to prioritize in Origin |
|---|---|---|---|
| Sidebar / navigation | Persistent left rail: workspace menu; Search and Create issue; Inbox, Reviews, My issues, Agent; Workspace links such as Projects, Views, Loops; team section with Home, Issues, Projects, Views; “More” and invite affordances. Team/workspace context remains visible while navigating. | Only unauthenticated landing/login is visible. Login has a small Origin brand link; no authenticated navigation could be assessed. | Build a persistent contextual rail with global destinations, team switcher, workspace/team link groups, selected state, compact badges, and a clear create-issue action. |
| Issue list / board | Team Issues has Active / Backlog / All issues tabs, custom-view affordance, Add filter, Display options, details toggle. Board groups into status columns; empty statuses can be hidden; cards show ID/title and selected metadata. Display menu toggles Board/List, grouping, subgrouping, ordering/direction, completed ordering, completed issue visibility, sub-issues, empty groups/columns, and display properties. Filters include status, assignee, agent/session, creator, priority, labels, relations, dates, project/properties, subscribers, external source, content, links, template, plus AI/advanced filters. | Unavailable behind login. | Offer list and board layouts that share a query model; add status grouping, configurable sort/grouping, filter builder, saved views, column/metadata visibility, and a way to show/hide empty groups/columns. |
| Density / row layout | No standalone density toggle was visible in the list display menu. Rows are intentionally compact; sampled issue-row wrapper measured about **36px high** in DevTools. Selected sidebar link container was about **220×28px**; that is the measured link box, not a separately measured outer rail. Font-size preference is configurable (default setting visible). | Unavailable behind login. | Keep rows compact, but expose a clear comfortable/compact density toggle and persist it per user/view. |
| Full-page issue | Opened by its canonical issue URL, not a peek. Top bar carries issue ID/title, favorite and issue-options controls, copy URL/ID/branch, copy-as-prompt, and coding-tool actions. Main center column has editable title and description, reaction/attachment controls, then Sub-issues and Activity. Right Properties panel holds status, priority, assignee, due date; separate Labels and Project sections. Activity includes subscribe controls, timeline entry, and comment composer. The sample had no linked external resources, so no links section/content was visible; keyboard menu exposes URL linking and links-section toggling. | Unavailable behind login. | Provide a durable issue route and a full issue page with clear title/description editing, stable property rail, activity/comment history, explicit child-issue section, and a dedicated links/relations area even when empty. |
| Labels / groups / colors | Settings → Issue labels has **New group** and **New label**, name filter, sortable Name / Description / Used in / Issues / Last applied / Created columns. Label picker separates Suggestions and Workspace labels. Create-label starts with a name field and description action; New group starts with a group-name field. Existing label menu included edit name, move to teams, view labeled issues, archive, delete. Visible dot colors: Bug red, Feature purple, Improvement blue. Sample labels were applied via picker/quick suggestions. | Unavailable behind login. | Add workspace/team label settings, groups, description, usage counts, reusable color dots, and a searchable multi-select picker with recently suggested labels. Make create/apply work from both settings and issue context. |
| Views | Team Views page offers Issues and Projects tabs and a Create new view action. Empty-state copy explains filter-based views that can be saved, shared, and favorited; existing views can be saved with Alt+V. | Unavailable behind login. | Add saved, shareable, favoritable filtered views and a useful empty state with a direct create action. |
| My issues | Tabs: Assigned, Created, Subscribed, Activity. Assigned view groups urgent, other active, and backlog; the created samples appeared under the appropriate active/backlog groups. | Unavailable behind login. | Add personal assigned/created/subscribed/activity queues with priority/status grouping and compact metadata. |
| Inbox | Two-pane layout. Controls include notification actions, unread-only, Add filter, Display options; empty state says “No notifications” with a separate “No notification selected” pane. | Unavailable behind login. | Use a two-pane inbox with unread/filter controls and distinct empty-list vs no-selection states. |
| Command menu / shortcuts | Ctrl/Cmd+K opens a searchable command palette contextual to the current issue. It included Assign to, Un-assign from me, Change status, Change priority, Add to project, Change/add labels, Change due date, and copy actions. “?” opens help; Keyboard shortcuts opens a searchable full shortcut reference. Relevant shortcuts observed: C new issue; A assign; I assign to me; S status; P priority; L labels; Shift+D due date; Ctrl+Shift+O sub-issue; Ctrl+K command menu; `/` search; G then I inbox; G then M my issues; O then I open issue; Space peek / Enter open focused item; Ctrl+B toggle list/board. | Unavailable behind login. | Add a searchable command palette and a discoverable `?` shortcut index; keep keyboard actions consistent and show the shortcut beside menu items. |
| Create issue / empty states | Compact modal with team, title, description, status, priority, assignee, project, labels, More actions, attachment control, Create more, Create. More actions exposes due date, links, recurring, and sub-issue. Quick suggestions appeared for Feature/Bug/Improvement based on title/description. Other observed empty states: inbox and custom views. | Login is the only accessible screen. It has Email and Password fields, Sign in, and Create an account; no Google sign-in option is visible. | Keep the issue composer fast and keyboard friendly; expose due-date and relation/sub-issue actions without leaving the flow. Give every empty page a clear explanation and next action. |
| Visual system / CSS | Dark theme; low-contrast charcoal surfaces, thin separators, restrained gray text, bright status/label dots, purple/blue primary accent. DevTools showed Inter Variable. Sampled sidebar/navigation font was 13px; root style panel showed `--content-bg-color: lch(2.595% 0.4 272)`, `--header-color: lch(5.52% 0.4 272)`, and `--header-height: 43px`. A list-row wrapper measured about 861×36px in the narrowed DevTools viewport. | Login screen uses near-black background, centered narrow form, white text, dark fields, lavender-purple primary button. No Origin app styles beyond login were examined. | Match Linear’s visual restraint: a consistent type scale, charcoal surfaces, subtle borders, soft text hierarchy, and one vivid accent. Keep small metadata readable and use color as an adjunct to labels/status text rather than as the only signal. |
