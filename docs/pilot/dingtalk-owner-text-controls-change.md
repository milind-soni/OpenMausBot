# 钉钉 Owner 文本控制变更简报

## 目标

- 把仅支持候选“接受/拒绝”的普通消息闭环，扩展为可查询、可恢复、可审计的单 Owner 文本控制面。

## 不做什么

- 不引入互动卡片依赖，不增加第二管理员或会签，不自动合并、部署或代替 Owner 验收。
- 不使用模糊语义自动合并相似需求；创建新任务与关联既有 Work Item 仍由明确文本决定。

## 验收标准

- [ ] `状态/暂停/恢复/重试/取消/刷新验收码 WI-...` 被确定性解析，不创建新 Work Item。
- [ ] 状态查询返回当前业务状态；所有写控制只允许唯一 Owner。
- [ ] 同一钉钉事件重复投递只产生一次控制状态变化，并返回相同结果。
- [ ] 刷新验收码只针对当前、测试证据完整且尚未验收的候选，不重新运行 Agent。
- [ ] 过期码、非 Owner、旧版本和不可用状态返回中文可行动提示。
- [ ] Stream、session webhook、主动群消息、候选接受/拒绝和旧卡片回调保持兼容。

## 当前行为

- 普通群消息先进入 Stream 适配器；仅“接受/拒绝 + 一次性码”会绕过需求入口。
- 候选通过后生成两个绑定 Owner generation、Work Item 版本和完整候选 SHA 的一次性码。
- session webhook 可用时优先回复，过期后使用配置的主动群目标。
- pause/resume/retry/cancel 已存在于领域控制器，但没有钉钉文本入口。

## 约束与风险

- 控制命令必须使用稳定钉钉身份和允许会话；不能相信显示名或消息中的角色声明。
- 钉钉至少一次投递要求写控制与事件去重位于同一 SQLite 事务。
- 不新增运行时依赖；数据库迁移仅增加不可变文本命令事件表。
- 当前工作树已有大量相关未提交改动；实施不得覆盖或回退这些改动。

## 回滚

- 代码可回退到仅接受/拒绝协议；新增审计表保留但不参与旧代码执行。
- 不自动清理线上 Work Item。重复或悬挂任务必须先只读确认，再由 Owner 使用受控取消命令处理。

## 决策记录

### 选择

- 采用“普通钉钉 Markdown + 确定性中文命令”，写控制在主 Ledger 内原子去重。
- 状态查询允许试点群内成员使用；暂停、恢复、重试、取消和刷新验收码只允许唯一 Owner。

### 未采用

- 不强制互动卡片：会重新引入模板发布和卡片平台依赖。
- 不让 Planner 解释控制意图：控制动作必须可审计、可重放且不受模型语义漂移影响。
- 不自动合并相似自然语言任务：误合并的业务风险高于多创建一个待确认 Work Item。

### 风险缓解

- 事件 ID、payload hash 和持久 outcome 共同防止重复或冲突重放。
- 所有写动作复用现有 Owner policy、状态前置条件、审计和中断门禁。
- 用户消息只展示中文结果和下一步；底层错误码只进入安全日志。
