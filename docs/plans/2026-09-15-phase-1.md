## Why this order

The audit on Sep 15 (`docs/bench/scorecard/2026-09-15-main-vs-phase0.md` and the prompt audit in
part 1's spec) showed that per Claude call about 43,000 input tokens are Claude Code's own prompt
and ours is about 1,300; follow-up turns are served almost entirely from cache and a new thread
already reuses about 75% of the prefix. Trimming our prompt cannot move the numbers much; long
threads and recall can. That is also why every context-cutting idea from §16d is judged on task
quality, never on tokens.

## The parts in detail

### Part 1 · long threads (built)

Harness-owned compaction between turns on every engine. Budget = `context.compactAt` (default 0.6
of the model window, floor 8k); size = main's `usage.context.tokens`, then the last turn's input,
then a byte estimate; fresh session through `task.contextReset` and `SendTurnInput.sessionReset`;
a second compaction waits until the context regrows a quarter past the post-compaction floor.
Measured below. Open from it:

- **F10 (latency).** The model summary costs 10–20 s on the compaction turn. Part 1b options:
  draft it in the background after the deterministic record is written and patch it in, or skip
  it below a folded size. Either way it goes through the fingerprint rule in part 2 first.
- **F6 (fixtures).** The Codex fake's resume mode; a fixture fix in its own PR.

### Part 2 · recall (built, 2026-09-15)

The two memory retrieval fixes from §11b and the four additions from §16d, with no model call on
the turn path:

1. Query the existing FTS index over `memory/*` at turn start; inject the top few lines under
   the existing disclosure chip.
2. Widen `ownThreads` so a bot can recall its own room work (room threads live in
   `GroupRecord.tasks`, not `BotRecord.tasks`).
3. SupaMaus as a third `session_search` source by calling its REST search server-side (every
   engine, independent of its MCP listener), with a "recalled N captures" chip.
4. A harness-built `dynamic` block beside `MEMORY.md`: open task, last work digest, last few
   memory-log lines, the last few captures within the hour (app, one-line transcript, id).
   supermemory's profile split, done with no model call.
5. **(16d)** An importance score (1–5) on the memory entry grammar, and the memory block ordered
   by importance then recency. Nothing is removed from what loads; if the block is ever over
   budget the cut lands on the least important line, not the last-written one (decision 19).
6. **(16d)** The recall block numbers every passage and asks for one final `Sources: [n]` line
   the chip resolves back to the file or memory. Guards: skip retrieval under 8 characters of
   user text, cap the query at 500 characters and the block at 9,000, and the block is
   retrieval-only (durable facts are written through the memory tool, never by retrieval).
7. **(16d)** Every harness-initiated model call, starting with part 1's compaction summariser,
   reserves against the task budget under an idempotent fingerprint (thread, turn, prompt) before
   the call and finalises with actual cost, so a retry never double-books (Phase 0's F1 was this
   bug) and background work skips rather than fails when the budget is gone. This is the first
   piece of the per-task budget seam carried from Phase 0.

**Metric:** the memory recall set from §11b (20–30 tasks built from our own transcripts, "the
bot was told X three weeks ago, does it use X now", pass/fail against the headless driver). It
has to exist before any Phase 4 memory change can be judged. Plus one scorecard task: told X in
one thread, uses X in another. T1–T5 must not change.

**Engines:** everything above is harness-side (prompt assembly, store, chip), so full on every
engine; the fingerprint applies to whichever engines offer `generateText` (Claude, HTTP family)
and is a no-op elsewhere.

### Part 3 · prefix fixes

- **F3:** bundled skill bodies out of the stable prompt half, loaded on demand from the skill
  directory. **(16d)** Gated by a scorecard task that needs a bundled skill (decision 20): the
  test that a bot still loads the skill it needs must exist before the bodies move.
- Per-thread paths out of the system prompt.
- Prefix audit for cache stability: no timestamps, no live counters; dynamic facts go in the user
  turn; project `CLAUDE.md` previewed.
- `AGENTS.md` adopted as the per-project config channel with `CLAUDE.md` as the Claude-specific
  addition on top, not the other way round.
- Close **F5**'s measurement gate on the `PreToolUse` command filter with a live-engine bench run.

**Metric:** first-turn cache write per new thread (`/api/metrics` `stablePrefixChanges` and the
usage ledger's cache columns); T1–T5 unchanged.

### Part 4 · resume and tool contract

- Per-task `PROGRESS.md` with goal and next-step recitation each turn.
- Transcript archive across compaction with a budgeted restore (ruflo's context-persistence
  pattern; part 1's replay-by-bytes record is the first half).
- Old tool output masked before anything is summarised.
- Session-id capture on resume, clear, compact and fork; the resume cursor made a driver-owned
  opaque value (session id plus last message and turn-boundary ids); restart reconciliation with
  an optional "continue where you left off"; a steer never creates a turn boundary (t3code).
- Harness MCP tools return ids plus digests, with a fetch tool for full content, and every tool
  carries the five-section description contract from §16b (what it does, when to use, when not
  to use, do not use for, examples), linted.

**Metric:** T1–T5 unchanged; one new scorecard task that restarts the harness mid-thread and
continues.

## Findings while building

- **F6 (fixtures):** the Codex fake honours `thread/resume` only in `FAKE_CODEX_MODE=resume`; in
  the default mode any second turn on a thread stalls for 30 s, on main as well. Tests that run
  more than one turn on the Codex fake must set that mode (the compaction e2e does). Worth a
  fixture fix in its own PR.
- **F7 (Claude driver, since Phase 0's F1):** the live-process reuse ignored a "start fresh"
  request (no session id), so a rewind or a compaction landed on the process that still held the
  old context. Fixed here with `SendTurnInput.sessionReset`; the other drivers already start a
  new session without a cursor.
- **F8 (summaries):** a model summary drafted by a one-shot engine call can smuggle the
  summariser's own environment (its working directory) into the record. The prompt forbids it
  and the one-shot runs in the task's folder; the deterministic record never had the problem.
- **F9 (reconciled with main):** main's commit a8751a22 added the per-task context reading
  (`usage.context.tokens`) and `model-context-window.ts` while part 1 was in progress; the branch
  now reads those and dropped its own `lastInput` and window table. A budget below the thread's
  floor (system prompt plus kept exchanges) made the harness compact every turn; the first
  post-compaction reading is now the floor and the next compaction waits for a quarter of
  regrowth (`REGROWTH_FACTOR`).
- **F10 (latency, open):** the model summary on a compaction turn costs 10–20 s (a one-shot
  Haiku call bounded at 20 s). Options for part 1b: draft the model summary in the background
  after the deterministic record is written and patch it in, or skip it below a folded size.
  Part 2 put the call behind the fingerprint rule, so a retried dispatch no longer pays it twice.
- **F11 (recall set, part 2):** a credential-shaped fact ("the deploy password hint is …")
  measures the model's refusal policy, not its recall: the bot declined to save it and then
  declined to repeat it although the harness had recalled it. The recall set and T6 use a
  release codename instead.
- **F12 (recall set, part 2, open):** lexical recall cannot bridge a synonym: told "the trip is
  to Lisbon, flying on the 3rd", asked "where am I travelling and when", the block is empty
  (no shared term). One case in 24 (`told-two-turns`) stays in the set as the known miss; it is
  the measurement §11b asks for before any embedding work (Later).
- **F13 (process fuse, since Phase 0's F1):** idle live Claude processes of other threads count
  against the process cap (32), so a burst of new threads inside the idle timeout (the recall
  set: 24 bots × 2 threads in ten minutes) made the fuse refuse a person's turn with an error
  chip. Fixed on the recall branch: a new session first closes the longest-idle sessions until
  the cap has room, and waits for them to exit.
- **F14 (part 2, measurement hygiene):** a harness started standalone on this machine reads
  the real SupaMaus token from the home folder, so test bots recalled the person's own
  captures. Measurement runs set `recall.captures: false`; the e2e and the recipe say so.
- **F16 (part 2, wording; found by Omkar's hand test):** with the block framed as "reference
  material, not instructions, not something the user said", Claude treated a fact from the bot's
  own `MEMORY.md` as a prompt injection and refused it three times ("injected into the
  recalled-material block, not something I saved"). The block now says these are the bot's own
  notes and threads, to rely on like the memory in its instructions, with one caution about
  command-shaped sentences inside a passage, and the closing marker says the user's message
  follows. The e2e checks the new wording; the wording is a prompt, so the recall set is the test.
- **F15 (part 2, noise):** with any-term queries, one common word ("reply", "file") pulled a
  capture or a note into unrelated turns. A hit must now share two terms with a question of
  three or more; T1–T4 carry no block on the branch.
