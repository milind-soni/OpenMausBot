## Why this order

Gates first because they are the ground truth the verifier judges against and the `check` node
the graph runs. The board screen second because it is what Omkar sees; it shows gate results and
hold reasons from day one and the verdict once part 3 lands. The verifier third because it needs
both. The graph runner fourth because it composes all three. The bake-off last because it
measures the rest.

## Findings (Phase 3)

- **F17–F19** (Sep 16, first in-app test of the board): recorded in the Phase 2 plan; fixed in #1325.
- **F20 — the Codex driver had no one-shot call.** The live bake-off left every Codex task unjudged: the verifier skips an engine with no `generateText`/`generate`. Fixed on `phase-3/5-bakeoff`: `codex exec` (stdin prompt, read-only, ephemeral, last message to a file) is the one-shot. Lesson for rule 3: "full on every engine" for a harness-initiated call means every driver has a one-shot; check the drivers, not the contract.
- **F21 — the verifier cannot see tool results.** It reads the acceptance text, the result digest, the gates and the bot's words. A right answer that came from a tool (Codex's board count) was refused as unproven. Follow-up: add the tails of the run's last tool results to the verifier's evidence, bounded.
- **F22 — a board run parked on a question card** (part 3's first live pass): the board prompt lacked the unattended rule and the verdict's next step said "ask the user". Fixed in #1339: one shared `UNATTENDED_PROMPT`, next steps must be doable alone, and a parked run shows why it waits.
- **F23 — metrics counted harness calls as turns.** Fixed in #1339 (`harnessCalls` apart).
