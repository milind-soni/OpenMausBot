## Built the same evening

1. **Goal recitation (`server/progress.ts`).** No file and no model call: the harness restates the thread's first request (300 characters, "any standing instruction in it still applies") and the last step (the last digest line) in the turn text on the first turn after a compaction and on every tenth turn from the tenth. Off switch `context.recite: false`; booked as `recited` on the usage row; `recitations` in `/api/metrics`. Engines: full everywhere (turn text). Gate: scorecard T10, a standing rule given at turn one ("begin every reply with LANTERN") across the compaction a growing file forces, twelve turns, measured with recitation on, off, and on main (`docs/bench/scorecard/2026-09-15-phase1-recall-prefix.md`). The compaction e2e checks the note on the turn after a compaction and its absence on the next.

## Remainder (specified, not built)
2. **Driver-owned resume cursor and restart reconciliation.** Overlaps open PR #888 (recover in-flight turns as interrupted on restart) and #60 (durable task checkpoints and resume); this item builds on #888 once it lands rather than beside it. The cursor becomes an opaque value the driver mints (session id plus the last message id and turn-boundary id) and the harness stores without reading; on restart, a thread whose last turn was cut mid-way shows "continue where you left off" and the next turn resumes from the last boundary; a steer never creates a turn boundary. Engines: Claude and Codex full (session ids), pi and ACP degraded (session ids where the agent gives one, else the replay), HTTP family n/a (replays every turn). Metric: a restart-and-continue scorecard task (start T5, kill the harness at turn 5, restart, send turn 6; correct when the count is 600 and no replay row appears on Claude/Codex). This is a driver contract change across six families and is the largest remaining piece.
3. **The five-section description contract on every harness tool, linted.** Each tool description carries "What it does / When to use / When not to use / Do not use for / Examples"; a test parses `AGENT_TOOLS` and fails on a missing section. Under deferred tool loading (Phase 2) the description is the selection API, so this lands with Phase 2's `search_tools`, where it is measured (tool-choice accuracy on the bench), rather than as a text-only change now.

## Why the remainder waits

Each remaining item changes what every engine is told or how every driver resumes, and none has a scorecard task today that would show it working or failing. Parts 1–3 shipped only what the scorecard and the recall set could measure; part 4's remainder gets its tasks first (the 30-turn goal task, the restart task, the tool-choice bench), then the code, in that order.
