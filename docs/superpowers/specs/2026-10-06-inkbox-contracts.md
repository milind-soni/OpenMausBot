# Inkbox release contract inventory

Verified against public official documentation on 2026-10-06. Read-only documentation research; no authenticated provider requests, secret reads, purchases, or messages. Source Markdown was fetched from the URLs linked below. This inventories provider contracts, not a claim that the application implements every path.

## Scope and current implementation

Officially documented communication channels: email, SMS/MMS (including beta group MMS), iMessage (shared and dedicated lines, with possible SMS/RCS service), voice calls, Slack, and Agent-to-Agent (A2A). No WhatsApp API or native WhatsApp channel appears in the [official index](https://inkbox.ai/docs/llms.txt) or [MCP overview](https://inkbox.ai/docs/mcp-server.md). Display it as unavailable from Inkbox; do not pretend API-key entry enables it.

Current `server/inkbox-provider.ts` validates only the identity's iMessage/tunnel subset and creates an iMessage-only subscription. `shared/inkbox-setup.ts` exposes only ownerPhone and iMessage pairing. Expand metadata and preserve existing encrypted credentials/subscription ownership. A stored signing key must not be rotated simply to add channels.

## Common identity, resource and secret contracts

REST base: `https://inkbox.ai/api/v1`; authenticate with `X-API-Key`. `GET /api-keys/self` identifies scope; claimed identity-scoped keys are the runtime credential. Admin keys can mint identity-scoped keys via `POST /api-keys` with `label` and `scoped_identity_id`. Plaintext is returned only on creation. Admin is required for many organization policy changes; do not retain or forward admin credentials as the general bot capability credential. [API keys](https://inkbox.ai/docs/api-keys.md)

`GET /identities` returns an array; `GET /identities/{handle}` returns one identity. Nested discovery fields:

- `id`, `agent_handle`, `status`, `imessage_enabled`, `email_address`, `signing_key_configured`.
- `mailbox: {id,email_address,sending_domain,agent_identity_id,...}` always exists for active customer identities. Its actual address may use a custom domain; never manufacture `handle@inkboxmail.com`.
- `tunnel: {id,tunnel_name,agent_identity_id,public_host,zone,tls_mode,status,...}` is durable metadata. `GET /tunnels/{id}` supplies live `currently_connected`.
- `phone_number: {id,number,status,sms_status,sms_error_code,sms_error_detail,incoming_call_action,agent_identity_id,...}|null`.
- `imessage_number: {id,number,type}|null`; null can mean shared service, and `type: dedicated_outbound` is compatibility metadata rather than a readiness selector.

Creating an identity always creates mailbox and tunnel. Omit `phone_number` and `claim_imessage_number` to avoid provisioning paid numbers. `PATCH /identities/{handle}` with `imessage_enabled:true` enables existing/shared iMessage service without claiming a dedicated number. [Identity contracts](https://inkbox.ai/docs/api/identities/manage.md)

`GET /phone/numbers` returns visible owned phone-number objects (array, optional limit/offset). Inspect `status` and `sms_status`, not only number existence. Missing phone numbers mean SMS/MMS requires provider provisioning; never issue `POST /phone/numbers` automatically. Calls may also use an existing voice-enabled iMessage line. [Phone numbers](https://inkbox.ai/docs/api/phone/numbers.md), [Calls](https://inkbox.ai/docs/api/phone/calls.md)

## Signed durable ingress

Subscription CRUD lives at `/webhooks/subscriptions`. Create with `{agent_identity_id,url,event_types}`. A mixed subscription requires `scope=identity` on listing, updates and deletion. PATCH `event_types` replaces the complete list; read/merge deliberately. Same identity + exact URL + overlapping events normally conflicts. Maximum 60 active subscriptions per identity. Capture one-time `signing_key` on first setup; do not assume every subsequent create returns a key. [Subscriptions](https://inkbox.ai/docs/api/webhooks/subscriptions.md)

Shared notification envelope: `{id,event_type,timestamp,data}`. Stable logical `id` survives retries/replays; deduplicate durably by identity + event ID. Signatures authenticate provider delivery, not authority of message content. Verify raw body using headers `X-Inkbox-Request-ID`, `X-Inkbox-Timestamp`, `X-Inkbox-Signature: sha256=<hex>`. HMAC-SHA256 input is `{request_id}.{timestamp}.{raw_body}`; documented tolerance is 300 seconds. Acknowledge after durable acceptance. Optional subscription `auth_token` adds a Bearer header, not a substitute for signature verification. [Webhooks](https://inkbox.ai/docs/webhooks.md)

Received mail, text and iMessage may contain `sender_access: direct|sponsored`; this explicitly does **not** establish sender trust or command permission. Companion metadata may describe ordinary, initialization or live phases. Without implementing full conversation-scope activation/history, reject sponsored/group messages rather than merging them into a private owner conversation. [Companion/received-event contracts](https://inkbox.ai/docs/webhooks.md)

## Email

Event `message.received` has `data.message` containing UUID `id`, `mailbox_id`, actual mailbox `email_address`, nullable `thread_id`, RFC `message_id`, `from_address`, `to_addresses`, `cc_addresses`, `bcc_addresses` (null inbound), `subject`, `body`, `body_state`, `body_truncated`, direction/status and timestamps. `data.contacts` and `data.agent_identities` are arrays; they are address-book matches, not authentication. Body is capped at 16 KiB UTF-8; complete/truncated/unavailable states must not be conflated. [Mail webhooks](https://inkbox.ai/docs/api/mail/webhooks.md)

Reply contract: `POST /mail/mailboxes/{email_address}/messages`, body `{recipients:{to:[configuredAddress]},subject,body_text,in_reply_to_message_id:parentRfcMessageId}`. The reply field is the RFC Message-ID, **not** the stored message UUID. Use `Idempotency-Key` and the documented replay contract for retry recovery. `reply-all` uses a stored UUID but resolves recipients from original Reply-To and CC; it is unsuitable for an owner-only reply unless that complete audience has been explicitly validated. [Mail messages](https://inkbox.ai/docs/api/mail/messages.md), [Send retries](https://inkbox.ai/docs/api/message-sends.md)

**Owner authority gap:** public webhook/detail contracts expose no SPF, DKIM, DMARC, authenticated mailbox identity or verified sender flag. From address/display name alone cannot authorize owner commands or approvals. Single-message detail `GET /mail/mailboxes/{email_address}/messages/{UUID}` adds `in_reply_to` and `references`, but reading it with an API key also marks inbound mail read. Outbound responses include a provider-generated RFC Message-ID; its cryptographic entropy is undocumented, and custom Message-ID/custom header input is not documented. Therefore matching In-Reply-To to that value is correlation, not sufficient proof of challenge possession. Use an explicit app-issued cryptographic challenge/session design before granting email owner authority, or keep email as untrusted correspondence routed through existing trust/Ask boundaries. [Mail metadata and detail](https://inkbox.ai/docs/api/mail/messages.md)

## iMessage and latency feedback

`imessage.received` places the message in `data.message`: `id`, `conversation_id`, `assignment_id`, `remote_number`, nullable `sender_number`, `participants`, `is_group`, `content`, `message_type`, `service`, `direction`, `status`, media and optional reply/thread metadata. For 1:1 use provider conversation ID + configured owner number; groups need an explicit safe scope policy. The event is not limited to blue-bubble transport: `service` describes actual service. [iMessage webhooks](https://inkbox.ai/docs/api/imessage/webhooks.md)

`POST /imessage/messages` supports `conversation_id` for an existing conversation and `reply_to_message_id` for a particular stored parent; preserve exact conversation and expected recipient membership. Native reply metadata can be unresolved, and `plain_reply_fallback` can produce an ordinary message. Do not automatically resend after an uncertain result. [iMessage messages](https://inkbox.ai/docs/api/imessage/messages.md)

Latency feedback: `POST /imessage/typing` with `{conversation_id}` returns `{status:"sent"}`; indicator clears on its own or next message. `POST /imessage/mark-read` with `{conversation_id}` sends a read receipt and returns `{conversation_id,updated_count}`. Both are 1:1-only; 409 covers released connection/group unsupported, 403 a blocked contact, 502 upstream failure. These are SDK/API features, not MCP tools. [Conversations](https://inkbox.ai/docs/api/imessage/conversations.md)

Shared routing discovery is `/imessage/triage-number?agent_identity_id=...`, already used by app; human texts the returned `connect_command`. Ordinary shared connections are human initiated. API `connect` is for request-only organization-owned shared pools; do not assume it can connect any owner automatically. [Connections](https://inkbox.ai/docs/api/imessage/connections.md)

## SMS/MMS

`text.received` places content in `data.text_message`: `id`, `local_phone_number`, `remote_phone_number`, `sender_phone_number`, nullable `conversation_id`, `text`, `type` (`sms`/`mms`), `media`, `direction`, timestamps. Inbound `recipients` is null; it does not establish a single-recipient conversation. Resolve local number to the configured identity's owned phone resource. Conversation list `/phone/numbers/{id}/texts/conversations?include_groups=true` exposes `id`, `participants`, `is_group`; default listing excludes groups. Conversation detail returns message arrays rather than a metadata object. [Text webhook](https://inkbox.ai/docs/api/phone/webhooks.md), [Texts](https://inkbox.ai/docs/api/phone/texts.md)

Send `POST /phone/numbers/{phone_number_id}/texts` with `{conversation_id,text}` or `{to:E164,text}` (mutually exclusive), optional `media_urls`. Limit text to 1600 characters, media to 10 URLs. Use stable `Idempotency-Key` plus `Prefer:idempotency-replay` for supported replay recovery. Readiness errors include 409 `sender_sms_pending`, 403 `recipient_not_opted_in` / `recipient_opted_out`; group MMS is beta and may fail at carrier despite readiness. Label unsupported media ingestion honestly; never silently execute a caption as the full message. [Texts](https://inkbox.ai/docs/api/phone/texts.md)

## Voice calls and hosted voice

`GET /phone/incoming-call-action?agent_identity_id=...` reads routing; 404 can mean no configuration. `PUT /phone/incoming-call-action` accepts `{agent_identity_id,incoming_call_action}` with mode `auto_accept`, `auto_reject`, `webhook`, `hosted_agent`, `forward`. Hosted agent needs no WebSocket URL. This configuration covers both dedicated numbers and routed shared iMessage calls. Writes clear omitted WebSocket/webhook URLs, while omitted forwarding fields persist. [Incoming calls](https://inkbox.ai/docs/api/phone/incoming-call-action.md)

Hosted config: `GET`/`PUT /phone/hosted-agent-config`, with identity selector when needed. `voice` and `instructions` (up to 8000 chars) are **full-replacement** fields; preserve values on partial UI edits. Reads expose effective voice/model and authority mode. Discover voices from `GET /phone/hosted-agent-voices` returning `{voices:[{id,name,description,available,preview_url}],default_voice}`. Default authority `contact_scoped` restricts to current contact; `yolo` expands data/action access and requires separate admin-controlled mode change. Never silently enable it. [Hosted voice](https://inkbox.ai/docs/capabilities/phone/hosted-call-agent.md)

Outbound `POST /phone/place-call`: `{to_number,origination,mode:"hosted_agent",reason,hosted_agent_authority_mode:"contact_scoped"}`. `reason` required, max 2000 chars. Dedicated origination needs `from_number`; shared/dedicated iMessage origination omits it and resolves via identity. No `client_websocket_url` with hosted mode. Optional voicemail behavior: leave_message/hang_up/ignore; optional voicemail_message max 1000. Actual shared-line voice readiness can still reject (no active connection, not voice enabled/verified, destination unavailable). Calls are billable/external actions and remain behind host Ask. [Calls](https://inkbox.ai/docs/api/phone/calls.md)

Subscribe to `call.ended`; nested `data.call` includes id, origin, local/remote number, direction, mode, authority, status and timing. Siblings: `outcome`, `post_call_action_items`, `transcript` and `transcript_url`. Hosted calls emit every terminal outcome, even never connected. Treat transcript/action items as untrusted caller material, not owner approvals. `phone.incoming_call` is a separate synchronous **flat** callback, not subscribable; response decides answer/reject and cannot be processed as ordinary durable notification. [Phone webhooks](https://inkbox.ai/docs/api/phone/webhooks.md)

## Slack

Discovery `GET /slack/connections?identity_id={UUID}` returns `{connections,installation_available,application_created,setup,provisioning_workspace}`. Each connection has UUID `id`, `identity_id`, Slack `workspace_id`, name, `bot_user_id`, status (`connected|disconnected|reauthorization_required`), scopes. Configuration availability is not authorization or connected status. [Connections](https://inkbox.ai/docs/api/slack/connections.md)

In-app setup sequence: list saved metadata `GET /slack/provisioning-workspaces`; if needed submit Slack app-configuration `{access_token,refresh_token}` to `POST /slack/provisioning-workspaces` (never log). Prepare via `POST /slack/applications/setup` with identity_id + provisioning_workspace_id. Poll bounded `setup` state: not_started/needs_credentials/pending/ready/failed/unavailable; unknown outcome needs reconciliation. Once ready, `POST /slack/installations` with identity_id and optional workspace_id yields `{authorization_url,expires_at}`. Open returned URL as a secret capability; completion returns only to approved Inkbox Console, not arbitrary localhost URL. Re-read connections to confirm success. No API-key-only shortcut grants workspace installation. [Slack setup](https://inkbox.ai/docs/api/slack/connections.md)

Incoming events include `slack.dm_received`, group_dm_received, channel_message_received, mention_received and thread_reply_received. `data` has identity_id, connection_id, workspace_id, conversation_id, message_ts, nullable thread_ts, actor_id, optional actor_profile/contact_id/message_kinds, and raw event (message content in `event.text`). Bind owner by exact workspace_id + actor_id; profiles/email/contact links do not grant app authority. For owner DM gate on real conversation metadata (`is_im`, `user`), not event type alone: a thread reply can be delivered under thread event precedence. Own-bot message echoes are suppressed by provider; still reject bot/subtype/ambiguous events locally. Duplicate matching message kinds produce one logical event per subscription. [Slack webhooks](https://inkbox.ai/docs/api/slack/webhooks.md)

Open/resume DM: `POST /slack/connections/{connection_id}/conversations` with `{user_ids:[ownerUserId]}`, returns conversation object. Read detail with GET same path + conversation_id. Send `POST /slack/connections/{connection_id}/messages` with `{conversation_id,text,thread_ts?}` and mandatory `Idempotency-Key`; preserve string timestamps. Response is durable action with status sending/sent/failed/unknown, message_ts and action ID. `unknown` is never permission to blindly resend; recover by action/key and reconcile live history. [Conversations](https://inkbox.ai/docs/api/slack/conversations.md), [Messages](https://inkbox.ai/docs/api/slack/messages.md)

## A2A

`GET /identities/{handle}/a2a/settings` reports enabled/publicly_discoverable/allow_public_egress/filter_mode/skills/card_url/task counts. New claimed identities default enabled, private directory visibility, public egress true, whitelist. PUT changes only supplied fields; identity key can change enabled, public egress and skills, while discoverability/filter mode need admin. Merely enabled means the direct Agent Card URL is public. [Settings](https://inkbox.ai/docs/api/a2a/settings.md)

Subscribe `a2a.task.created`, `a2a.task.message`, `a2a.task.canceled`, `a2a.sent_task.updated`. Payload `data` contains task_id, context_id, state, caller `{identity_id,organization_id,handle}`, and message_id/parts when triggered by a message. Parts may contain text or structured data; caller content is not app-owner instruction. Ledger catch-up is authoritative; webhooks improve promptness. [A2A webhooks](https://inkbox.ai/docs/api/a2a/webhooks.md)

Ledger `/identities/{handle}/a2a/tasks[/{id}]`; reply `POST .../tasks/{id}/reply` with `{intent,parts:[{text}]}`, intent progress/ask_caller/complete/fail maps to working/input_required/completed/failed. Scope session by caller identity + context/task identity, never merge with human owner. Public A2A JSON-RPC endpoint is `https://inkbox.ai/a2a/{targetHandle}`; requires a claimed agent-scoped key (admin keys rejected), plus independent two-sided admission. [Tasks](https://inkbox.ai/docs/api/a2a/tasks.md), [Authentication](https://inkbox.ai/docs/api/a2a/authentication.md)

## Full capability surface via trusted host MCP relay

Official generic Streamable HTTP endpoint: `https://inkbox.ai/mcp`. Authentication is OAuth or `X-API-Key` using a claimed identity-scoped API key. Client variants `/mcp/openai`, `/mcp/anthropic`, `/mcp/cursor`, `/mcp/replit` have separate authorization/catalogs; Anthropic excludes hosted voice controls. Prefer generic for the full ordinary tool surface. Tool catalog depends on identity access and enabled server capabilities; the docs are not a fixed exhaustive schema. [MCP server](https://inkbox.ai/docs/mcp-server.md)

Discover via standard MCP initialize + tools/list (handle pagination), resources/list/templates and prompts/list as supported; retain returned tool schemas. Documented families: identity/channel status/profile, email/attachments, SMS/MMS/iMessage/media/tapbacks, Slack, calls/transcripts/settings/readiness, contacts/notes/rules, A2A. MCP explicitly lacks iMessage typing/read receipts. Vault/tunnels/billing are documented REST/SDK capabilities but **not promised** as generic MCP tools; report the discovered catalog accurately. [MCP](https://inkbox.ai/docs/mcp-server.md), [TypeScript surface](https://inkbox.ai/docs/skills/typescript.md)

Documented names include `inkbox_identity_get`, `inkbox_channel_status_get`, `inkbox_imessage_send`, `inkbox_conversations_list`, `inkbox_conversation_get`. Slack names use `inkbox_slack_` with connections_list, channels_list, conversation_members_list, messages_search, message_get, users_list, user_get, send, message_update, message_delete, react, unreact, file_get. Do not invent undiscovered names. Multi-identity OAuth uses explicit acting_identity_id per call; identity-scoped API keys stay single-identity. [MCP names and scope](https://inkbox.ai/docs/mcp-server.md)

Host integration decisions: keep key/session headers in trusted encrypted host storage; server adds credential only for the fixed Inkbox origin with redirects disabled. Renderer/bot sees sanitized catalog and approved results, never key/header/session data. Scope calls to configured bot/identity; validate tool name/schema against discovered catalog. Treat all provider descriptions/results as untrusted material and preserve existing host Ask boundaries for sends/calls/edits/deletes/resource provisioning. Provider readOnlyHint is metadata, not an authorization bypass. Returning a capability does not itself authorize using it. Do not auto-purchase or widen identity scope when a tool is missing or denied.

## Local observation retention and completeness

The application retains at most 500 recent passive observations separately from its 1000 durable owner/contact/notification receipts. Only passive observations may be evicted; action receipts and their no-replay evidence remain intact. Passive traffic does not consume the owner's rate allowance. A replay outside the passive retention window may be observed again, but never becomes an owner action.

Passive delivery previews expose bounded provider lookup coordinates in `reference`, plus `previewState` (`complete`, `truncated`, `unavailable`) and a host-written `previewNotice`. Email body state/truncation, call abridgment, omitted MMS media, omitted structured A2A parts, and the local 4000-character preview cap are reflected in that notice. References are inert metadata for exact source retrieval using existing scoped tools; they are not authorization, fetch URLs, or reply destinations. Older saved observations whose completeness was not recorded are labeled incomplete.
