# Waits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bot can say "tell me when…": three tools (`wait_until`, `list_waits`, `cancel_wait`) hand a condition to a server loop that checks it with plain code, and when it is met the asking chat gets one message, an unread badge, a notification and, if the bot was given `then`, a follow-up run in that chat.

**Architecture:** `server/wait-probes.ts` reads files, the process list and web pages (the page read resolves the host itself, refuses non-public answers and connects to the address it checked). `server/waits.ts` holds `WaitManager` on the `CalendarCallManager` pattern: `DATA_DIR/waits.json`, a 5 s tick, per-kind intervals, an `ending` that is saved before it is posted so a restart never posts twice. `server/wait-host.ts` is the store side (the line, the card, the notification, the follow-up run through `routines.enqueueWebhook`). `server/routes/waits.ts` is the internal route behind the tools; `server/index.ts` gains about 20 lines of wiring and no path guard.

**Tech Stack:** TypeScript on Node with type stripping (type-only imports must be `import type`), zod 4, vitest 4, React for one renderer line.

**Spec:** `docs/superpowers/specs/2026-10-27-waits-design.md`

**Worktree:** `/Users/omkar/Desktop/openmaus/OpenGrokBot-bot-waits`, branch `feat/bot-waits`. Run every command from there. Never push.

## Global Constraints

- No model call between set-up and firing. The tick, the probes and the posting run no AI.
- Everything is named "wait". Never "watch" (`watch.json` and the Watcher bot exist).
- Kinds, exactly: `url_contains`, `url_missing`, `file_exists`, `file_missing`, `file_changed`, `process_running`, `process_gone`, `bot_idle`.
- URL checks: http(s) only, at least 60 s apart, doubling on each failure up to 15 min, reset to 60 s on success; 15 s timeout; 2 MB read cap; no cookies; at most 3 redirects, each hop checked again. The host is resolved by the probe, every answer must be a public address, and the request connects to the checked address (pinned `lookup`, no second lookup).
- File, process and `bot_idle` checks every 5 s (the tick). Paths accept `~`.
- `hours`: integer 1–168, default 24. Limits: 10 active waits per bot, 50 in all.
- `DATA_DIR/waits.json`, mode `0o600`, `writeFileAtomic`, zod-validated on load, commit with rollback.
- Fired line: `<label>: done. <detail>`. Expiry line: `Stopped waiting for <label> after N hours.` (no notification, no follow-up). Follow-up prompt: `[Wait finished: <label>] <then>`.
- Bot and chat come from the internal capability, never from tool arguments. Waits are made and cancelled only in a turn a person started in their own one-to-one chat with the bot (or a Cloud guest's own turn); rooms, routine runs, peer asks, handed-off work and outside events are refused.
- File and process kinds are refused when the server is not the bot's own computer: Cloud home, hosted workspace, Cloud guest, or a turn working in a Local VM, VPS or Boat.
- No new `path === "/…"`, `path.match(`, `path.startsWith(` in `server/index.ts` (`scripts/testing/index-route-ratchet.test.ts`). The route lives in `server/routes/waits.ts`.
- Comments only for what code cannot say (`AGENTS.md`). Doc comments on new wire fields in `shared/`.
- No phone app changes in this repository. Phones get the `notify` frame and the feed as they are; drawing the wait card on phones is a separate `SupaMaus/mausbot-mobile` change.
- Decided here (the spec left them open): waits do not keep a sleeping Cloud home awake (`nextDueAt` unchanged); `waits.json` is left out of workspace backups and Cloud sends; on a Cloud home the follow-up does not join the person's chat but runs and reports like any outside event there (its own "<label> · Results" chat), because that is the Cloud home's rule for outside events; `bot_idle` treats "waiting on you" as working, since `ACTIVITY_BUSY` does.

## Review Focus

1. The condition is met while the person is mid-turn in that chat: the line must wait for the chat to be free, then appear once. Task 3 ("holds the line…") and Task 4 ("holds the line while a turn runs") pin it.
2. The server stops between deciding a wait fired and posting it: after restart, one line and one follow-up, not two. Task 3 ("holds the line…", reload from file) and Task 4 (post skips a line already there) pin it.
3. The chat, the bot, or the bot waited for is deleted while waiting: drop silently without recreating the chat; say so when the other bot is gone. Task 3 ("drops a wait silently…", "stops with a line…") pins it.
4. A host that resolves to a public and a private address, a redirect to loopback, `localhost`, `[::1]`: all refused. Task 2 pins it.
5. A relative path, a Windows `.exe` name, a Linux 15-character process name, a macOS full path in `ps`: Task 1 and Task 5 pin them.

- [ ] **Step 3: Implement `fetchPageText`**

Defaults: `lookup = resolveTarget`, `allow = ({ address }) => addressClass(address, ownAddresses()) === "public"`. One `AbortSignal.timeout(timeoutMs)` covers every hop. Each hop:
1. Parse; protocol not `http:`/`https:` or a username/password present → `{ ok: false, refused: true, error: "Only an http or https address with no sign-in details can be checked." }`.
2. `host = url.hostname` without `[ ]`; `addresses = await lookup(host)`; none → `{ ok: false, refused: false, error: "That address could not be found." }`.
3. Any address failing `allow` → `{ ok: false, refused: true, error: \`${host} points at this computer or a private network, which waits never check.\` }`.
4. `http(s).request(url, { agent: false, signal, lookup: <always answers addresses[0]>, headers: { "user-agent": "OpenMausBot-wait", accept: "text/html,text/plain;q=0.9,*/*;q=0.1" } })`, the pinned-lookup shape of `server/custom-domain.ts:99-102`.
5. 3xx with `location`: next hop from `new URL(location, url)`; a fourth redirect → the "redirected too many times" error. Other non-2xx → `The page answered <status>.`
6. 2xx: collect chunks until `maxBytes`, then destroy the response and use what was read; `pageText(utf8)`.
An abort → `The page took too long to answer.`; any other socket error → `{ ok: false, refused: false, error: "The page could not be reached." }`.

Copy (exact):
- `describeCondition`: `<url> says “<text>”`, `<url> no longer says “<text>”`, `<path> exists`, `<path> is gone`, `<path> changes`, `<process> is running`, `<process> has stopped`, `<botName> finishes its work`.
- Already true: `` `${describeCondition(c)} already. Nothing was set up: tell the person now.` ``
- Fired detail after `<label>: done. `: `<url> now says “<text>”.`, `<url> no longer says “<text>”.`, `<path> is there now.`, `<path> is gone.`, `<path> changed.`, `<process> is running.`, `<process> stopped.`, `<botName> finished.`
- Expired: `` `Stopped waiting for ${label} after ${n} hour${n === 1 ? "" : "s"}.` `` with `n = Math.round((expiresAt - createdAt) / 3_600_000)`.
- Stopped (the other bot is gone): `` `Stopped waiting for ${label}: ${botName} no longer exists.` ``
- `waitList` line: `` `- ${id} · ${label} · until ${describeCondition(c)} · made ${iso(createdAt)} · stops ${iso(expiresAt)}${then ? ` · then: ${then}` : ""}` `` (`iso` = `new Date(ms).toISOString()`).
- Per-bot limit: `` `You already keep ${WAIT_LIMITS.perBot} waits, the most one bot may:\n${waitList(mine)}\nCancel one with cancel_wait first.` ``; total: `This computer already keeps 50 waits, the most it holds. Ask the person which ones to stop.`
- Unreachable page at creation, `note`: `` `The page could not be read just now (${error}); checks go on every minute and slow down while it keeps failing.` ``
