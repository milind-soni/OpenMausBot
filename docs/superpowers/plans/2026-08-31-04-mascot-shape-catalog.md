# Mascot Shape Catalog Implementation Plan

> **Naming note (2026-09-01):** the code vocabulary for this feature is `body`, not
> `shape` — `mascotBody`, `MASCOT_BODIES`, `MascotBodyId`, `shared/mascot-bodies.ts`,
> `scripts/mascot-bodies/`, `MausBodies.swift`. The repo enforces
> `anti-slop/no-shape-in-symbol-names` as an error, and `body` is the word this document
> already uses in prose. Identifiers written as `mascotShape` etc. below are the original
> design text and are stale; the ids themselves (`cursor`, `blob`, …) are unchanged.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every bot a choice of ten body shapes — plus a mode where its own uploaded image becomes the body with the live face still on top — rendered identically on desktop and iOS.

**Architecture:** A Node generator solves each shape's face placement once (signed distance field + the existing fit solver) and emits two checked-in catalogs, one TypeScript and one Swift. Both renderers already accept a pluggable silhouette and an anchored face, so they become lookups over that catalog rather than hardcoded single shapes. The image body reuses the clipPath the renderer already builds for the face.

**Tech Stack:** TypeScript, React, Node 22 (`--experimental-strip-types`), Vitest, Zod 4, SwiftUI (`Canvas`), pnpm.

**Spec:** `docs/superpowers/specs/2026-08-31-mascot-shape-catalog-design.md`

```ts
/**
 * The ten catalog outlines, as absolute cubic path data.
 *
 * Adapted from Blob Studio's studio/src/shapes/builtin.ts at fixed parameters.
 * Cubics only, because the phone's twenty-line path parser understands `M`, `C`
 * and `Z` and nothing else — emitting anything richer here would mean growing a
 * parser on the platform least able to afford it.
 */

/** Quadratic control point to its exact cubic pair. */
function quadToCubic(
  x0: number, y0: number, cx: number, cy: number, x1: number, y1: number
): [number, number, number, number, number, number] {
  return [
    x0 + (2 / 3) * (cx - x0), y0 + (2 / 3) * (cy - y0),
    x1 + (2 / 3) * (cx - x1), y1 + (2 / 3) * (cy - y1),
    x1, y1,
  ]
}

/** A straight run as a degenerate cubic, so the emitted path stays cubics-only. */
function lineToCubic(
  x0: number, y0: number, x1: number, y1: number
): [number, number, number, number, number, number] {
  return [x0 + (x1 - x0) / 3, y0 + (y1 - y0) / 3, x0 + (2 * (x1 - x0)) / 3, y0 + (2 * (y1 - y0)) / 3, x1, y1]
}

/** Circular-arc magic number: four cubics approximate a circle to ~0.02%. */
const KAPPA = 0.5522847498307936
```

Then a small path builder that accumulates `M`/`C`/`Z` and rounds coordinates to 5 decimals, and the ten definitions:

- `cursor` — the literal artwork string. ## Task 3: Flattening, bounds and the fit transform

**Files:**
- Create: `scripts/mascot-shapes/geometry.ts`
- Test: `scripts/mascot-shapes/geometry.test.mjs`

**Interfaces:**
- Consumes: nothing.
- Produces:
  ```ts
  export interface Bounds { minX: number; minY: number; maxX: number; maxY: number }
  export function flatten(d: string, tolerance?: number): [number, number][][]
  export function boundsOf(polylines: [number, number][][]): Bounds
  export function fitTransform(bounds: Bounds): { transform: string; scale: number; tx: number; ty: number }
  export function applyFit(polylines: [number, number][][], fit: { scale: number; tx: number; ty: number }): [number, number][][]
  ```

`fitTransform` reproduces the mapping in Blob Studio's `measureFit`: scale the drawn bounds to fill the face box on its tighter axis, then centre it. The emitted string is `translate(<tx> <ty>) scale(<scale>)`, matching the shipped `DEFAULT_SILHOUETTE.fit` format so the renderer needs no change.

## Task 4: Rasterise a polyline into a mask

This replaces Blob Studio's `rasterise`, which draws through an `<img>` and a canvas. We know the outline analytically, so a scanline fill is both sufficient and dependency-free.

**Files:**
- Create: `scripts/mascot-shapes/raster.ts`
- Test: `scripts/mascot-shapes/raster.test.mjs`

**Interfaces:**
- Consumes: `flatten`, `boundsOf`, `fitTransform`, `applyFit` from Task 3.
- Produces:
  ```ts
  export function maskFromPolylines(polylines: [number, number][][], size?: number): Uint8Array
  ```
  Returns `size * size` bytes, `1` inside. Coordinates are face-space; `size` defaults to `256`.

Use the **non-zero winding rule**, matching how SVG fills by default.

Create `scripts/mascot-shapes/raster.test.mjs`:

```js
import { describe, expect, it } from "vitest";

import { maskFromPolylines } from "./raster.ts";

const FACE_BOX = 228.541;
const SIZE = 256;

/** A circle of radius r centred in the face box, as a dense polygon. */
const circle = (r, steps = 512) => {
  const c = FACE_BOX / 2;
  const points = [];
  for (let i = 0; i < steps; i++) {
    const a = (i / steps) * Math.PI * 2;
    points.push([c + Math.cos(a) * r, c + Math.sin(a) * r]);
  }
  return [points];
};

const at = (mask, x, y) => {
  const px = Math.floor((x / FACE_BOX) * SIZE);
  const py = Math.floor((y / FACE_BOX) * SIZE);
  return mask[py * SIZE + px];
};

describe("maskFromPolylines", () => {
  it("fills the inside and leaves the outside clear", () => {
    const mask = maskFromPolylines(circle(80));
    expect(at(mask, FACE_BOX / 2, FACE_BOX / 2)).toBe(1);
    expect(at(mask, 4, 4)).toBe(0);
  });

  it("covers the area the circle actually has", () => {
    const r = 80;
```

  ```ts
  export const mascotShapeSchema: z.ZodEnum<...>
  ```

**Solve parameters.** `Avatar.tsx` defaults to `forward: true`, which cancels each expression's authored gaze and gives the pointer its full range (`POINTER_GAZE.forward = 1`). So solve with `lookAround: 0`, and because a pointer can be in any direction, solve at each of the four extreme aims `(±1, ±1)` and keep the **worst** scale. A single centred solve would produce a face that clips when someone moves the mouse.

**The clamp.** After solving all ten, take the minimum scale across the catalog, then re-solve each shape's *anchor position* at that fixed scale (sweep anchors, keep the one with the best clearance). Fail if the shared scale is below `cursor`'s own solved scale.

**The assertion.** Fail the generator if `report()` finds any clipping expression for any shape at its final anchor.

```swift
static func inFaceBox(_ id: String) -> Path {
```
