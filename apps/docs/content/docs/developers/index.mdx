MausBot's bots are not only for the app. You can give one a job from a script, send it a message from your own server, or let another agent coordinate your team.

Pick the way in that fits where your code runs.

## Client SDKs

Talk to one bot from your own code, through its [Bot API](/docs/developers/bot-api). Both packages are called `mausbot`.

<Cards>
  <Card title="TypeScript" href="/docs/developers/sdks/typescript" description="No dependencies. Node 18+, Bun, Deno and edge runtimes." />
  <Card title="Python" href="/docs/developers/sdks/python" description="Sync and async clients on httpx. Python 3.9+." />
</Cards>

| SDK | Package | Version |
|---|---|---|
| TypeScript | `mausbot` on npm | `0.1.0` |
| Python | `mausbot` on PyPI | `0.1.0` |

Each major SDK version uses one Bot API version.

## Building agents?

The bots you already have are the agents. See [Bots, folders, and threads](/docs/features/bots-and-tasks) for how they work and [Routines and webhooks](/docs/features/automation) to run them on a schedule or from an outside event.

<Callout type="warn" title="Keep a Bot API key on a server">
  A key reads whatever its bot can read: the bot's instructions and memory, through its replies. Keep it on a server, never in a browser page or an app bundle. A key marked **Acts as me** is as powerful as the owner: anyone holding it can make the bot do anything its level allows.
</Callout>
