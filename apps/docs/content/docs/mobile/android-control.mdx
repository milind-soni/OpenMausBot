MausBot can expose a USB or paired wireless Android device through its Phone Harness skill. A supported agent can inspect the screen, open apps, tap, long-press, type, swipe, scroll, and capture screenshots.

## USB setup

- A physical Android device connected over USB
- USB debugging enabled on the device
- The computer trusted from the device's debugging prompt
- The packaged Android platform tools or a compatible local ADB installation

Phone access is a separate capability from desktop computer use. Keep the device unlocked and visible while testing, and review actions that may send messages, change accounts, or expose private content.

## Wireless setup

On Android 11 or later, enable **Wireless debugging** in Developer options and choose **Pair device with pairing code**. On this computer, use Android platform tools to run `adb pair HOST:PAIRING_PORT` and enter the code at its prompt. Keep the phone and computer on the same Wi-Fi.

Run `adb devices -l` and copy the connected service name ending in `._adb-tls-connect._tcp`. Set the environment variable `PH_ANDROID_SERIAL` to that exact name before starting OpenMausBot. For example, in PowerShell:

```powershell
$env:PH_ANDROID_SERIAL = 'adb-EXAMPLE-random._adb-tls-connect._tcp'
```

Fully quit OpenMausBot, start it from that shell, and ask it to check the phone. If the service name is missing, check that wireless debugging and mDNS discovery are available. Clearing the variable and restarting restores USB-only operation. Pairing codes are entered directly into Android platform tools.

To install an app, put its APK in the conversation working folder and ask the bot to install it. Android checks the signature on updates and keeps the existing app data.

## Screen and lock

A bot can turn the screen on and off. It never unlocks a PIN, pattern, or password lock: it asks you to unlock the phone.

## Typing other languages

The bot types letters, digits, spaces, and `_.,@-` through Android's own input. For other text, such as Chinese, emoji, or `+`, install [ADBKeyBoard](https://github.com/senzhk/ADBKeyBoard) on the phone and switch it on in the keyboard list. Your usual keyboard can stay chosen: the bot switches to ADBKeyBoard while it types, and back. If a call is cut off in between, the phone can be left on ADBKeyBoard, which shows no on-screen keyboard: choose your keyboard again in the phone's settings. A keyboard with several languages may come back in its default language. While it is the keyboard, ADBKeyBoard also takes typing from any app on the phone, not only from OpenMausBot, so use it only on a phone whose apps you trust.

With ADBKeyBoard 2.0 or later, the bot can also empty a field before it types, for example to replace the words in a search box. It taps the field first. Without ADBKeyBoard it has to remove old text one character at a time.

Some apps draw their own text box and do not tell the keyboard what it holds. The bot cannot empty such a box, so check the screen after it types there. ADBKeyBoard's older APK also restarts when asked to; the builds on its [release page](https://github.com/senzhk/ADBKeyBoard/releases) (v2.4-dev and newer) check for this.
