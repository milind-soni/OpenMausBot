The Electron app starts a local harness and serves the interface from the same machine. The normal port is `8799`. If another process already owns it, a source-run harness may select a fallback port automatically; packaged and CLI launches do not.

## App opens but never becomes ready

1. Quit every OpenMausBot window.
2. Confirm no old OpenMausBot process remains.
3. Start the app once and wait for the local harness.
4. If it still fails, inspect the desktop log.

On macOS, packaged logs are under `~/Library/Logs/OpenMausBot`. On Windows they are under the OpenMausBot log directory in `%APPDATA%`.

## Port overrides and fallback

`OMB_PORT` sets the preferred port for a source-run harness (and `OMB_WEBHOOK_PORT` the preferred webhook port). If the preferred port is unavailable, a source-run harness walks forward to the next free port and logs the resolved value.

`OMB_DESKTOP_PARENT=1` and `OMB_PORT_PINNED=1` disable that fallback: the child stays on the requested ports and exits with an `EADDRINUSE` error if either is busy. The `openmausbot serve` CLI and the packaged desktop parent set `OMB_PORT_PINNED=1` so proxies, pairing URLs, and the parent health check all target the port they configured.

## Isolate a test profile

Developers can set `OMB_DATA_DIR` to run against a clean OpenMausBot data directory. This is useful for reproduction and screenshots without touching a real workspace.
