MausBot is local-first by default: the harness listens on loopback, agent CLIs run on your machine, and application state lives under `~/.openmausbot`.

If you only want to use a remote Docker desktop while MausBot and its agents stay on your current computer, follow [Your own VPS (BYO)](/docs/computers/byo-vps) instead.

## Typical self-hosted setup

1. Run MausBot on your personal macOS, Windows, or Ubuntu computer.
2. Install and authenticate the agent CLIs you want to use separately; the npm OpenMausBot package does not include them. Use the same operating-system account for setup and the running server.
3. Add optional third-party keys only for the services you need.
4. Keep the harness on loopback.
5. Use it from other devices by pairing them. `openmausbot serve` prints one pairing link for the way in you choose; paste it into the desktop app under **＋ → Connect to a server**, open it in a browser, or scan its QR with a phone.

| You have | Run |
|---|---|
| HTTPS in front already (cloudflared, Caddy, nginx) | `npx openmausbot serve --public-url https://maus.example.com` |
| A domain name, ports 80 and 443 open | `npx openmausbot serve --domain maus.example.com` |
| Tailscale | `npx openmausbot serve --tailscale` |
| Only this network | `npx openmausbot serve --lan` |
| Nothing at all | `npx openmausbot login`, then `npx openmausbot serve --tunnel` |

A code works once, for 10 minutes. `npx openmausbot pair` makes another, and `npx openmausbot devices` lists the paired devices. See [Deploy on a VPS](/docs/self-hosting/deploy-vps) for a server from scratch, and [Networking](/docs/self-hosting/networking).

For a Linux service, the VPS guide covers [account setup](/docs/self-hosting/deploy-vps#before-you-start), [browser installation](/docs/self-hosting/deploy-vps#give-the-bots-a-browser-optional), and [unattended startup](/docs/self-hosting/deploy-vps#keep-it-running). Installing browser libraries as administrator still requires installing the browser in the service user's home. The service runs an installed, chosen release; upgrading it is an explicit step.

Stop the server before a filesystem backup. Application state under `.openmausbot` is only part of a complete backup: preserve the service user's engine credentials, browser state, and external workspaces too. See [Data and backups](/docs/self-hosting/data-and-backups).

## What is still third party

Self-hosting MausBot does not self-host every optional provider:

- Agent providers authenticate and bill through their own CLI or API.
- Composio owns connected-app OAuth grants unless you replace that integration.
- Boat owns managed cloud computers.
- ElevenLabs or Fish Audio synthesizes speech when its hosted voice engine is enabled. On Windows and Linux, Fish Audio also turns what you say into text for Take turns calls and dictation.

These services are optional. Local chat through a locally installed agent CLI does not require them.

## Run headless during development

```bash
pnpm install --frozen-lockfile
pnpm dev:server
```

The main harness listens on `127.0.0.1:8799` by default. Keep it private; it owns agent processes, approvals, computers, and workspace configuration.
